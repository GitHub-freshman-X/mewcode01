# MewCode 工具系统 Spec

## 背景

MewCode 已经具备基础命令行对话能力：用户可以在终端中进行多轮流式对话，程序通过统一的模型后端边界接收规范化事件，并在会话中维护上下文。

当前能力仍停留在纯文本问答。用户让模型查看项目、修改文件或运行命令时，模型只能给出建议，不能实际操作工作区。本章要把 MewCode 从聊天机器人推进到可执行任务的 Agent 雏形：模型可以根据用户请求选择工具，程序负责执行工具，并把执行结果回灌到对话历史中，让模型基于真实结果给出下一步回应。

## 目标

- 提供统一工具抽象，使每个工具都能声明名称、描述、参数约束和执行行为。
- 内置六个核心工具：读文件、写文件、改文件、执行命令、按模式找文件、搜索代码内容。
- 提供集中注册中心，统一登记工具、按名称查找工具，并生成模型 API 可识别的工具定义列表。
- 在模型流式响应中识别工具调用，正确拼接分片 JSON 参数，并在工具调用完成后执行对应工具。
- 将工具执行结果以结构化消息回灌到对话历史，使模型能基于结果继续回答。
- 工具执行必须具备超时、失败捕获和结构化错误结果，避免工具失败导致程序崩溃。
- 文件修改采用原文唯一匹配替换：匹配不到或匹配多次时返回清晰错误，让模型能调整参数后重试。
- 本章文档存放于 `docs/ch03/`。

## 功能需求

- **F1 统一工具接口**：系统提供统一工具能力边界。每个工具都能暴露稳定名称、面向模型的描述、参数 Schema，以及接收结构化参数并返回结构化执行结果的行为。
- **F2 核心工具集合**：系统内置六个工具，分别支持读取文本文件内容、写入文本文件内容、通过原文替换修改文本文件、执行本地命令、按 glob 或同类模式查找文件、按文本或正则模式搜索代码内容。
- **F3 工具注册中心**：系统提供集中注册中心，用于登记所有可用工具、拒绝重复名称、按名称查找工具，并把当前可用工具转换为模型请求需要的工具声明列表。
- **F4 工具参数校验**：工具执行前必须根据工具自身声明的参数约束校验输入。缺少必填参数、参数类型错误或参数值不合法时，不执行工具动作，并返回结构化失败结果。
- **F5 工具执行超时**：每次工具执行都有超时限制。超时后系统终止或取消该次执行，并向模型返回可识别的超时结果。
- **F6 工具错误结构化**：工具执行失败时，系统返回包含工具名称、成功状态、错误类型、错误信息和必要上下文的结构化结果，而不是让错误冒泡导致对话流程崩溃。
- **F7 读文件工具**：模型可以请求读取工作区内指定路径的文本文件。成功时返回文件内容和基础元信息；路径不存在、不可读、目录路径、二进制或过大文件应返回清晰错误。
- **F8 写文件工具**：模型可以请求向工作区内指定路径写入文本内容。成功时返回写入路径和字节数；非法路径、父目录不存在、权限不足或写入失败应返回清晰错误。
- **F9 改文件工具**：模型可以请求在工作区内指定文本文件中，把一段原文替换为新文本。系统必须要求原文在文件中恰好出现一次；出现零次或多次时不得修改文件，并返回能指导模型重试的错误。
- **F10 执行命令工具**：模型可以请求执行本地命令。成功或失败都返回退出状态、标准输出、标准错误和是否超时；命令启动失败、运行失败或超时不得导致 MewCode 崩溃。
- **F11 找文件工具**：模型可以请求按模式查找工作区文件。结果应可限制数量，并在无匹配、模式非法或搜索失败时返回结构化结果。
- **F12 搜索代码工具**：模型可以请求按内容模式搜索工作区文本文件。结果应包含匹配文件、匹配位置和片段，并能限制返回数量；模式非法或搜索失败时返回结构化错误。
- **F13 流式工具调用解析**：模型后端流式返回工具调用时，系统能够识别工具调用开始、名称、调用标识和参数 JSON 分片，并在流结束或工具调用完成信号到达时拼接成完整参数。
- **F14 工具调用执行与回灌**：当一次模型回复包含工具调用时，系统执行对应工具，并把工具结果作为新的对话历史消息追加进去，供后续模型请求使用。
- **F15 单轮工具边界**：本章只支持一次模型回复中的工具调用执行与结果回灌。模型拿到一次工具结果后，本轮流程停止，不自动再次请求模型形成多步 Agent Loop。
- **F16 用户可见状态**：当模型请求工具、工具正在执行、工具成功或失败时，界面能向用户展示当前状态和结果摘要，使用户知道 MewCode 正在实际操作。
- **F17 供应商边界延展**：工具声明、工具调用流事件和工具结果回灌应通过统一模型后端边界表达，上层对话流程不直接依赖单一供应商的原始事件格式。

## 非功能需求

- **N1 安全边界**：所有文件读取、写入、修改、查找和搜索默认限制在当前工作区内，不允许通过相对路径逃逸到工作区外。
- **N2 可控输出**：工具结果返回给模型和展示给用户时应限制体积，避免超大文件、海量搜索结果或命令输出撑爆上下文或界面。
- **N3 响应性**：工具执行期间界面保持可刷新，并能展示执行中状态；长时间命令通过超时结束，不无限挂起。
- **N4 稳定性**：工具参数 JSON 不完整、无法解析、工具不存在、工具内部错误、命令异常退出、文件系统错误都不得导致程序崩溃。
- **N5 可测试性**：工具接口、注册中心、六个核心工具、参数校验、超时、错误结果、流式工具调用分片拼接和历史回灌都能在不访问真实模型服务的情况下自动测试。
- **N6 可扩展性**：新增工具时只需实现统一工具能力并注册，不需要改动 TUI 核心流程或每个模型后端的调用方。
- **N7 可诊断性**：错误结果应足够具体，能说明失败阶段和可重试方向，但不得泄露不必要的环境细节或敏感信息。
- **N8 跨平台兼容**：文件工具和命令工具应兼容 macOS、Linux 和 Windows 的路径、换行和进程行为差异；平台差异需要以清晰错误或测试约束表达。

## 不做的事

- 不做自动循环 Agent Loop；工具结果回灌后不自动继续请求模型。
- 不做并行多轮工具调用编排、计划器或任务队列。
- 不做用户审批每一次工具调用的交互流程。
- 不做权限策略配置、沙箱隔离、容器执行或远程执行。
- 不做 Git 专用工具、补丁格式应用、语义代码编辑或 AST 级重构。
- 不做图片、音频、PDF 等非文本文件解析。
- 不做长期文件索引、向量检索或后台代码库索引服务。
- 不做对话历史持久化、工具执行日志持久化或审计数据库。
- 不做多个工具结果触发的新一轮模型自动调用；该能力留到后续章节。
- 不承诺兼容所有 OpenAI-compatible 或 Anthropic-compatible 服务的工具调用变体；本章以已支持 Provider 的官方工具调用语义为准。

## 验收标准

- **AC1（F1）**：任一工具都能通过统一能力边界暴露名称、描述、参数 Schema 并执行；测试工具可以被注册、调用并返回结构化结果。
- **AC2（F2）**：六个核心工具均可被注册中心列出，并能分别完成读文件、写文件、改文件、执行命令、找文件和搜代码的成功场景。
- **AC3（F3）**：注册重复工具名称时返回错误；按已注册名称可找到工具；按未知名称查找时返回可识别的未找到错误；生成的工具声明可被模型请求使用。
- **AC4（F4）**：对每个核心工具提供缺少必填参数或参数类型错误的输入时，工具动作不执行，并返回结构化校验失败结果。
- **AC5（F5）**：配置一个会超过超时限制的命令或测试工具时，执行会在超时后结束，并返回标记为超时的结构化结果。
- **AC6（F6）**：模拟文件系统错误、命令启动错误和工具内部错误时，对话流程不崩溃，模型历史中收到结构化失败结果。
- **AC7（F7）**：读取存在的工作区文本文件时返回完整或受限内容；读取不存在路径、目录、工作区外路径、二进制或过大文件时返回清晰错误。
- **AC8（F8）**：写入合法工作区文本文件后，文件内容与请求内容一致；写入工作区外路径、父目录不存在路径或不可写路径时不产生意外文件并返回错误。
- **AC9（F9）**：当原文在目标文件中恰好出现一次时，文件被正确替换；当出现零次或多次时，文件保持不变，并返回匹配数量相关错误。
- **AC10（F10）**：执行成功命令时返回退出状态、标准输出和标准错误；执行失败命令时返回非零退出状态和输出；超时命令返回超时标记。
- **AC11（F11）**：按文件模式搜索时返回匹配路径并遵守数量限制；无匹配和非法模式返回结构化结果。
- **AC12（F12）**：按内容模式搜索时返回文件、位置和片段并遵守数量限制；无匹配、非法模式或搜索失败返回结构化结果。
- **AC13（F13）**：使用分片返回工具调用参数的测试流时，系统能拼接出完整 JSON 参数；分片 JSON 无法解析时返回可诊断错误。
- **AC14（F14）**：模型请求工具后，系统执行工具，并把包含调用标识和工具结果的消息追加到对话历史；下一次模型请求能看到该工具结果。
- **AC15（F15）**：工具结果写入历史后，本轮不会自动再次请求模型；用户再次提交输入时才发起下一次模型请求。
- **AC16（F16）**：在界面中触发工具调用时，用户能看到工具名称、执行中状态、完成或失败摘要，并在完成后继续输入。
- **AC17（F17）**：同一套上层对话流程可以处理来自已支持模型后端的工具调用事件；TUI 和会话层不解析供应商原始 SSE 事件。
- **AC18（N1、N2、N4）**：工作区外路径、超大输出、未知工具、 malformed JSON 和工具异常都被自动化测试覆盖，且不会导致未处理 panic 或界面退出。
- **AC19（N5、N6）**：注册一个新的测试工具不需要修改现有核心工具代码；工具系统、Provider 工具事件解析和对话历史回灌均有不访问真实 API 的自动化测试。
