# MewCode Agent Loop Spec

## 背景

MewCode 已具备多轮流式对话、统一 Provider 边界，以及工具注册、执行、结果回灌能力。但当前一次用户请求只进行一轮模型调用：模型调用工具后，系统执行并写回结果，随后停止，必须等待用户再次输入才能继续。

本章引入 Agent Loop，使 MewCode 能在单次任务内反复调用模型、执行工具并依据结果调整行动，直到形成最终回答或触发停止条件。

## 目标

- 支持完整 ReAct 循环，让单次任务可自主完成多个推理与工具执行步骤。
- 通过异步事件流解耦 Agent 执行与界面展示。
- 实时输出文本，同时保留每轮完整响应用于循环判断和历史提交。
- 安全调度一次响应中的多个工具调用。
- 支持只读规划、随后执行的 `/plan` 与 `/do` 两阶段工作流。
- 为循环提供明确、可观测的停止边界，避免失控运行。

## 功能需求

- **F1 Agent 任务入口**：系统提供独立于界面的 Agent 执行入口，接收用户任务、会话上下文、可用工具和循环配置，并返回异步事件流。
- **F2 ReAct 循环**：每轮调用模型并收集完整响应；若模型请求工具，则执行工具、写回调用及结果并继续下一轮；若模型不再请求工具，则以最终文本完成任务。
- **F3 停止条件**：以下任一情况发生时必须停止循环并给出明确原因：
  - 模型返回不含工具调用的完整响应；
  - 达到迭代上限，默认 20 轮且可配置；
  - 用户取消任务；
  - 连续出现 3 次未知工具调用；
  - 模型流读取或解析出错。
- **F4 未知工具计数**：每个未知工具调用计一次；成功解析到已注册工具时重置连续计数。达到阈值后不再发起下一轮模型调用。
- **F5 取消传播**：用户取消后，系统停止当前模型流或工具执行，不启动尚未开始的工具，并结束整个 Agent 任务。
- **F6 历史提交边界**：只有完整收集并成功处理的模型轮次才进入后续模型上下文。取消或流错误产生的部分响应可供界面展示，但不得提交到模型历史。
- **F7 异步事件流**：Agent 对外发出规范化事件，至少覆盖：
  - 文本增量；
  - 工具调用；
  - 工具执行结果；
  - Token 用量；
  - 当前轮次与执行阶段等进度；
  - 任务完成、取消和失败等终态。
- **F8 双路流式收集**：模型文本到达时立即作为增量事件发给消费者，同时在内部累积完整响应，用于识别工具调用、提交历史和决定是否继续循环。
- **F9 多工具安全调度**：一次模型响应包含多个工具调用时，系统按原始顺序划分执行批次：
  - 连续的只读工具组成一个批次并发执行；
  - 具有副作用的工具各自形成串行批次；
  - 后续批次必须等待前一批次全部结束；
  - 工具结果按模型原始调用顺序写回上下文。
- **F10 工具安全分类**：读取文件、查找文件、搜索代码属于只读工具；写文件、改文件、执行命令属于有副作用工具。未明确分类的工具默认按有副作用处理。
- **F11 工具失败反馈**：已知工具执行失败时，结构化结果仍写回模型，由模型决定调整参数、改用其他工具或结束任务；该失败本身不终止循环。
- **F12 Token 用量汇总**：当 Provider 提供用量信息时，系统发出每轮用量事件，并维护任务级累计值，至少区分输入与输出 Token。
- **F13 `/plan` 规划阶段**：`/plan <任务>` 启动只读 Agent Loop，只向模型开放读文件、找文件和搜代码工具；模型可多轮探索，但最终只能产出计划，不能修改工作区或执行命令。
- **F14 计划保存**：成功完成的 `/plan` 结果作为当前会话的最近计划保存；取消、失败或达到安全停止条件的规划不得覆盖此前有效计划。
- **F15 `/do` 执行阶段**：`/do` 使用当前会话最近一次有效计划启动新的 Agent 任务，恢复全部工具；不存在有效计划时返回清晰提示且不调用模型。
- **F16 界面解耦**：TUI 仅根据 Agent 事件更新文本、工具状态、Token 和进度，不负责驱动下一轮模型调用或决定工具执行顺序。

## 非功能需求

- **N1 响应性**：模型生成和工具执行期间，界面持续接收事件并保持可取消；只读工具并发执行不得阻塞文本和进度展示。
- **N2 稳定性**：模型流异常、事件消费者退出、工具 panic、工具超时、未知工具及取消竞争均不得导致程序崩溃或遗留失控任务。
- **N3 确定性**：并发工具可以按任意顺序完成，但对外结果事件和写回模型上下文的顺序必须与原始工具调用顺序一致。
- **N4 上下文一致性**：每轮 assistant 响应必须与其全部工具结果成组提交；不得向后续模型请求暴露半轮或缺失调用标识的历史。
- **N5 可测试性**：Agent Loop、所有停止条件、双路收集、事件顺序、工具分批调度和 Plan Mode 均可在不访问真实模型服务的情况下自动测试。
- **N6 Provider 中立**：Agent 层只依赖统一模型边界，不解析 Anthropic 或 OpenAI 的原始流格式；两个现有 Provider 应表现出一致的循环语义。
- **N7 可扩展性**：新增界面消费者不应修改 Agent 循环；新增工具只需声明安全分类并注册，未声明时自动采用保守策略。
- **N8 可诊断性**：终态事件必须包含可识别的停止原因、已完成轮数和累计 Token；失败信息应保留诊断价值但不泄露凭据。
- **N9 资源回收**：任务完成、取消或失败后，相关模型流、工具执行和事件生产必须退出，不得遗留持续工作的后台任务。
- **N10 配置兼容**：未配置 Agent 参数时采用安全默认值；现有模型、Token 和 Thinking 配置继续有效。
- **N11 回归兼容**：普通非命令输入自动使用完整 Agent Loop；现有纯文本回复、思考内容和工具状态仍可在 TUI 中展示。

## 不做的事

- 不做工具权限策略、细粒度授权、沙箱隔离或每次调用前的用户确认。
- 不做上下文压缩、摘要、裁剪或长会话 Token 预算管理。
- 不做工具调用失败后的自动重试策略；失败结果交给模型判断下一步。
- 不做有副作用工具的事务、回滚或补偿机制。
- 不分析多个工具调用之间的隐式依赖，也不构建任务 DAG；仅按安全分类和原始顺序分批。
- 不做多个 Agent 并行协作、后台任务队列或跨会话任务恢复。
- 不持久化计划；最近计划仅在当前进程的当前会话中有效。
- 不提供计划编辑、逐步骤审批或交互式确认流程。
- 不做基于 Token 数量或费用的动态停止；本章只采集并报告用量。
- 不新增工具，也不改变第 3 章各工具自身的工作区、超时和输出限制。
- 不保证取消能够撤销已经完成或正在产生外部副作用的工具动作；取消只阻止后续工作并尽力终止当前操作。

## 验收标准

- **AC1（F1、F16）**：使用不依赖 TUI 的测试消费者提交任务时，可仅通过 Agent 事件观察完整执行过程；移除 TUI 后循环仍能自主推进。
- **AC2（F2）**：模拟“调用读工具 → 根据结果调用写工具 → 返回最终文本”的模型序列时，系统自动完成全部轮次，中途无需用户再次输入。
- **AC3（F3）**：模型返回不含工具调用的完整响应后，任务以“正常完成”停止，且不再请求模型。
- **AC4（F3）**：模型持续请求工具时，系统在配置的迭代上限停止；未配置时恰好最多调用模型 20 轮，并报告“达到迭代上限”。
- **AC5（F3、F5）**：在模型生成、只读批次或副作用工具执行期间取消任务，系统均进入取消终态，不启动剩余工具或下一轮模型调用。
- **AC6（F3、F4）**：连续调用未知工具 3 次时任务停止并报告原因；中间出现已注册工具后，连续计数从零重新开始。
- **AC7（F3）**：模型流读取或解析失败时，任务进入失败终态，不执行从不完整响应中得到的工具，也不继续下一轮。
- **AC8（F6）**：取消或流错误前已产生的文本可通过事件被消费者看到并标记为部分输出，但下一次模型请求的上下文中不存在该不完整响应。
- **AC9（F7）**：覆盖完整多轮任务的事件记录中，可观察到文本增量、工具调用、工具结果、Token 用量、轮次进度和唯一终态，且终态之后不再出现普通事件。
- **AC10（F8）**：文本分片到达后立即出现在事件流中；同一轮结束时，内部完整响应与全部分片拼接结果一致，并据此正确判断是否继续循环。
- **AC11（F9、F10）**：一次响应按“读、读、写、读、执行命令”的顺序请求工具时，前两个读工具并发，写工具单独执行，后一个读工具在写完成后执行，命令最后执行；结果按原始顺序写回。
- **AC12（F10）**：注册未声明安全分类的测试工具时，该工具按有副作用工具串行执行，不进入并发只读批次。
- **AC13（F11）**：已知工具返回失败结果后，该结果被写回模型，系统继续下一轮；模型随后可更换参数并成功完成任务。
- **AC14（F12）**：模拟两轮均报告输入、输出 Token 的模型响应时，每轮产生用量事件，终态中的累计值等于两轮之和。
- **AC15（F13）**：执行 `/plan <任务>` 时，模型请求只包含三个只读工具；模型可多轮读取项目并最终输出计划，工作区内容保持不变。
- **AC16（F14）**：成功规划后可取得最近计划；之后一次取消或失败的规划不会覆盖该计划。
- **AC17（F15）**：成功规划后执行 `/do`，模型收到最近计划并可使用全部六个工具，直至完成或触发安全停止条件。
- **AC18（F15）**：当前会话没有有效计划时执行 `/do`，界面显示清晰提示，不调用模型或工具。
- **AC19（N2、N4、N9）**：取消竞争、工具 panic、工具超时、消费者停止读取和流错误测试均不产生未处理崩溃、半轮历史或持续运行的后台任务。
- **AC20（N5、N6、N10、N11）**：不访问真实模型即可测试全部循环场景；Anthropic 与 OpenAI 适配器均能提供 Agent 所需规范化事件；原有普通文本、Thinking 和工具展示回归测试通过。
