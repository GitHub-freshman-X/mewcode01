# MewCode MCP Client Spec

## 背景

MewCode 已具备统一工具接口、注册中心、权限门禁和 Agent Loop，但工具来源仅限内置实现。用户需要通过配置声明外部 MCP Server，使 MewCode 能在启动时发现其工具，并像调用内置工具一样供 Agent 使用。

本章引入一个 MCP 客户端：从已选定的主配置文件读取 Server 配置，连接 stdio 子进程或 Streamable HTTP 服务，完成 MCP 初始化和工具发现，并把发现结果接入既有工具中心。

## 目标

- 支持 stdio 与 Streamable HTTP 两种 MCP Server 传输。
- 按 JSON-RPC 2.0 完成初始化、工具发现和工具调用，并按请求 ID 正确关联异步响应。
- 在 `config.yaml` 中与 `protocol`、`model` 等主配置字段同级声明 `mcp_servers`；不读取项目级 MCP 覆盖文件。
- 支持配置值中的 `${VAR}` 环境变量展开。
- 让远端工具以 `<server>__<tool>` 的稳定名称注册为现有工具，并通过既有权限门禁和 Agent Loop 使用。
- 隔离单个 Server 故障；不做健康检查、自动重连或 HTTP 会话恢复。

## 功能需求

- **F1 配置发现**：启动时仅从已选定的 `config.yaml` 顶层读取 MCP Server map；未声明时视为空配置，不读取项目级 MCP 覆盖文件。
- **F2 配置校验与变量展开**：支持 `stdio`（`command`、`args`、`env`）和 `http`（`url`、`headers`）两类声明；校验必填字段与传输类型，并在连接前展开 `${VAR}`。缺失变量只使对应 Server 不可用。
- **F3 stdio 连接**：为每个 stdio Server 启动独立子进程，通过标准输入输出以换行分隔的 JSON-RPC 消息通信；stderr 仅用于安全诊断。
- **F4 Streamable HTTP 连接**：为每个 HTTP Server 使用配置 URL 和 headers 发起 MCP 请求；维护服务端提供的会话标识，并将其用于后续请求。
- **F5 JSON-RPC 会话**：生成唯一请求 ID，正确关联乱序到达的响应；将协议错误、无效消息、取消和传输中断转换为相应请求的失败，而不影响其他 Server。
- **F6 初始化与发现**：对每个可连接 Server 执行 MCP 初始化握手、完成初始化通知、列出工具；仅在完整成功后暴露该 Server 的工具。
- **F7 远端工具适配**：把每个发现到的工具包装为现有 Tool 接口，保留描述与输入 Schema；注册名固定为 `<server>__<tool>`，并默认标记为有副作用。
- **F8 远端调用**：Agent 调用适配工具时，客户端向原 Server 发起 `tools/call`，将参数原样传递；把文本、结构化内容、MCP 错误和调用失败转换为现有的结构化工具结果。
- **F9 注册冲突与隔离**：远端命名空间与内置或其他远端工具冲突时，不覆盖既有工具；故障 Server 不注册工具，也不阻止其他 Server 或内置工具工作。
- **F10 连接缓存与生命周期**：已成功初始化的连接在本次 MewCode 进程生命周期内复用；关闭程序时关闭 stdio 子进程和 HTTP 会话。不会进行健康检查、自动重连、HTTP 会话恢复或失败调用重试。
- **F11 可诊断性**：连接、初始化、发现、配置与调用失败必须按 Server 和阶段提供可观察、无敏感信息泄露的诊断；MewCode 继续运行。
- **F12 现有能力兼容**：未配置 MCP Server 时保持当前启动与内置工具行为；远端工具继续通过已有权限门禁、Agent Loop、Plan/Do 工具集合和结果回灌路径。

## 非功能需求

- **N1 协议兼容**：实现 MCP 所需的 JSON-RPC 2.0 消息语义；stdio 严格使用每行一个 JSON 消息；HTTP 请求保留配置 headers 并正确处理 MCP 会话标识。
- **N2 故障隔离**：一个 Server 的配置、进程、网络、协议或调用故障不得阻塞其他 Server 的发现、内置工具执行或 Agent Loop 后续轮次。
- **N3 安全性**：不得在日志、事件或工具结果中泄露 HTTP Authorization、配置 headers、展开后的环境变量值或子进程环境；远端工具默认走有副作用权限路径。
- **N4 并发正确性**：同一 Server 的多个未完成 JSON-RPC 请求必须按 ID 正确配对；不同 Server 的请求可独立进行，关闭过程不得产生数据竞争、悬挂等待或子进程泄漏。
- **N5 可测试性**：不依赖真实外网或第三方 MCP 服务，即可通过受控 stdio/HTTP 测试 Server 验证握手、发现、调用、错误、乱序响应、配置加载、变量展开和关闭生命周期。
- **N6 确定性**：相同配置、环境和受控 Server 响应下，注册工具集合、命名、调用结果和失败分类保持稳定。
- **N7 兼容性**：不含 MCP 配置的现有配置文件仍可加载；第 2 至第 6 章的既有测试与行为继续有效，除非有明确、经过测试的兼容性调整。
- **N8 可维护性**：传输差异局限在传输适配层；会话、协议、配置、工具适配和生命周期职责分离，使后续增加资源、提示词或采样能力不必重写工具接入路径。

## 不做的事

- 不实现 MCP 资源、提示词、采样、根目录、任务、授权或其他非工具能力。
- 不做 Server 健康检查、后台保活、自动重连、HTTP 会话失效后的自动恢复，或失败工具调用自动重试。
- 不支持 SSE 旧式 HTTP 传输；仅支持 stdio 与 Streamable HTTP。
- 不提供图形化的 MCP Server 配置、连接状态管理或手动重连界面。
- 不实现用户、团队或远程共享的 MCP 配置同步与管理。
- 不为远端工具添加自定义安全分类；全部默认有副作用，并复用既有权限系统。
- 不修改现有内置工具的名称、行为、权限规则语义、Agent Loop、Plan/Do 工作流或模型 Provider 协议。
- 不在配置失败时将 MCP Server 配置静默替换为更宽松的默认值。
- 不做跨进程或跨启动的 MCP 连接持久化缓存；缓存只存在于当前 MewCode 进程。
- 不把缺失环境变量、协议不兼容或连接失败伪装成可用工具。

## 验收标准

- **AC1（F1、F2）**：给定包含多个 Server 的 `config.yaml`，最终 Server 集合与该文件声明一致；非法声明或未展开变量仅跳过对应 Server，并产生不含敏感值的诊断。
- **AC2（F3、N1）**：受控 stdio Server 接收到换行分隔的有效 JSON-RPC 初始化、初始化完成、列工具及调用消息；子进程 stderr 不会污染协议通道。
- **AC3（F4、N1）**：受控 Streamable HTTP Server 收到配置 headers 和正确 JSON-RPC 请求；初始化响应给出会话标识后，后续发现与调用请求均带该标识。
- **AC4（F5、N4）**：同一连接上并发发送两个不同 ID 请求且响应乱序返回时，每个等待方均得到与自身 ID 对应的结果；未知 ID、JSON-RPC error、无效响应或传输中断只使关联请求失败。
- **AC5（F6）**：成功 Server 完成初始化、初始化完成通知与 `tools/list` 后才注册远端工具；握手或发现失败的 Server 不注册任何工具，其他 Server 与内置工具仍可用。
- **AC6（F7、F9）**：发现的 `search` 工具被注册为 `<server>__search`，描述和输入 Schema 可被 Provider 看见；与内置或其他 Server 名称冲突时不覆盖既有工具。
- **AC7（F8）**：经 Agent 调用远端工具时，服务端收到相同参数的 `tools/call`；成功内容、MCP 工具错误、JSON-RPC 错误和传输失败均返回现有格式的结构化工具结果，并能继续回灌 Agent Loop。
- **AC8（F10、N2）**：多个 Server 中一个启动、发现或调用失败时，其余工具照常执行；同一 Server 成功连接只复用一个会话；进程关闭后 stdio 子进程退出且 HTTP 会话按协议关闭。
- **AC9（F10）**：Streamable HTTP 会话失效（404）时，不自动重新握手、刷新工具、重试或重连；本次调用返回结构化失败。
- **AC10（F11、N3）**：配置、连接、握手、发现和调用失败均能看到 Server 名与失败阶段；诊断和结果不包含 Authorization 值、header 值、环境变量展开值或完整子进程环境。
- **AC11（F12、N7）**：未声明 MCP 配置时，当前应用启动、内置工具、权限门禁、Plan/Do 以及既有自动测试行为保持可用；远端工具默认按有副作用请求权限。
- **AC12（N5、N6、N8）**：通过本地受控 stdio/HTTP Server 的自动化测试重复执行相同场景，注册名称、调用次数、结果与失败分类一致；传输与协议测试可分别运行。
