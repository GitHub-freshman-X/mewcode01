# 测试运行目录隔离 Spec

## 背景

`cmd/mewcode` 的启动测试会初始化与真实 CLI 相同的日志和会话存储。若测试保留 Go 测试进程默认的包目录作为当前工作目录，这些运行产物会被写入源码目录，造成 `cmd/mewcode/.mewcode/` 与 `cmd/mewcode/logs/` 残留。

## 目标

- 启动测试的运行产物只写入测试专用的临时目录。
- 运行 `go test ./cmd/mewcode` 后不在源码包目录留下 `.mewcode` 或 `logs`。

## 功能需求

- F1：任何会调用完整启动流程并创建日志或会话的 `cmd/mewcode` 测试，都必须在测试专用工作目录中执行。
- F2：配置覆盖、权限成功、权限失败和配置失败等启动测试仍须保持各自现有的行为断言。
- F3：自动化验证须能确认运行整个 `cmd/mewcode` 测试包后，源码 `cmd/mewcode` 目录没有由测试生成的 `.mewcode` 或 `logs`。

## 非功能需求

- N1：测试不得访问真实模型、真实用户配置目录或网络。
- N2：测试运行目录隔离不得改变用户从任意当前目录启动 CLI 时，日志和会话仍落在该当前项目目录的既有行为。
- N3：不新增运行时配置项、环境变量、依赖或生产代码抽象。

## 不做的事

- 不改变 CLI 对当前工作目录作为项目根目录的定义。
- 不清理用户手动运行 CLI 时已生成的运行目录。
- 不修改其他包的测试运行策略，除非它们复现同一问题。

## 验收标准

- AC1（F1、F3）：在源码包目录不存在目标运行目录时执行 `go test ./cmd/mewcode -count=1`，测试通过且随后仍不存在 `cmd/mewcode/.mewcode` 与 `cmd/mewcode/logs`。
- AC2（F2）：配置覆盖、权限成功、权限失败和配置失败测试继续保持其既有退出码、配置路径或错误消息断言。
- AC3（N1、N2、N3）：测试使用临时目录和替身 Provider；完整 CLI 启动时仍以用户当前目录作为项目根；不新增配置或生产代码路径。
