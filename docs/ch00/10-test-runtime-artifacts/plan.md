# 测试运行目录隔离 Plan

## 架构概览

本次只修改 `cmd/mewcode` 的测试装配。生产启动入口继续从进程当前目录取得项目根；所有直接调用 `run` 且未隔离工作目录的启动测试，在调用入口前临时切换到 `t.TempDir()`，使 logger、会话存储及其他启动期运行数据都写入测试目录。

## 模块设计

### `cmd/mewcode/main_test.go`

**职责：** 为配置覆盖、权限成功、权限失败和配置失败场景建立隔离的项目根，并在测试结束后恢复测试进程原工作目录。

**交互：**

1. 每个未隔离的启动测试保存当前工作目录。
2. 测试切换到各自的 `t.TempDir()`；需要用户配置目录的成功路径同时替换为临时目录。
3. 测试配置既有启动替身并调用 `run`。
4. 启动流程按既有语义将日志与会话写入临时目录。
5. `defer` 恢复原目录和全局替身；测试继续断言配置路径、退出码或错误消息。

## 文件组织

```text
cmd/mewcode/
└── main_test.go  — 配置覆盖启动测试的工作目录隔离与回归断言
```

## 技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 隔离位置 | 每个直接调用 `run` 的测试中切换至 `t.TempDir()` | 覆盖启动早期 logger 创建和成功路径会话创建，且不改变 CLI 的真实项目根语义。 |
| 生产代码 | 不修改 | `os.Getwd()` 是 CLI 当前目录语义的一部分，不是缺陷。 |
| 回归验证 | 定向测试后检查源码包目录 | 直接覆盖用户观察到的 `logs/` 与 `.mewcode/` 残留。 |

## Spec 覆盖

| Spec | 实现归属 |
|---|---|
| F1、F2 | 四条未隔离启动测试的临时目录切换和既有行为断言 |
| F3、AC1 | 完整 `cmd/mewcode` 包测试前后检查源码包目录运行目录 |
| N1、N2、N3 | 复用现有替身与启动入口，不修改生产代码或配置 |
