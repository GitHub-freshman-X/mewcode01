# 启动猫头横幅 Spec

## 背景

当前启动横幅实现将猫头写入 TUI 外的终端诊断输出，用户无法在 TUI 内看到它。用户希望猫头成为 TUI 初始界面中的独立视觉元素，而不是对话消息。

## 目标

- 在 MewCode 启动 TUI 后，于初始消息区域直接展示固定的 ASCII 猫头。
- 使用用户确认的图案：

  ```text
   /\\_/\\
  ( o.o )
   > ^ <
  ```

## 功能需求

- F1：每次正常启动 MewCode 并打开 TUI 后，初始消息区域直接展示一次固定的三行 ASCII 猫头。
- F2：猫头是 TUI 的独立视觉元素，不作为系统消息、用户消息或模型消息显示，也不写入会话历史、模型请求或结构化日志正文。
- F3：退出、创建会话、清空会话或恢复会话后，猫头不重复插入；它只显示在当前 TUI 进程的初始界面中。

## 非功能需求

- N1：不新增配置项、外部依赖或运行时状态。
- N2：输出内容在 macOS、Linux 和 Windows 的 ANSI 兼容终端中保持普通文本可读。
- N3：增加无需真实模型服务的自动化测试，覆盖初始 TUI 渲染、会话隔离和入口不输出横幅。

## 不做的事

- 不提供自定义图案、颜色、开关或动画。
- 不将猫头实现为可持久化、可选择或可被模型读取的消息。
- 不改变除初始猫头以外的 TUI 布局、交互、会话持久化、日志字段或启动流程。

## 验收标准

- AC1（F1）：使用有效配置启动并打开 TUI 后，初始消息区域恰好显示一次已确认的三行猫头，行序和字符一致。
- AC2（F2）：猫头不具有消息标签或消息背景，不出现在会话记录、系统消息、模型输入或结构化日志内容中。
- AC3（F3）：在同一 TUI 进程执行会话创建、清空或恢复后，猫头不重复显示。
- AC4（N1、N2、N3）：入口诊断输出不再包含猫头；新增 TUI 测试和全项目测试通过，且显示不依赖颜色或特定终端能力。
