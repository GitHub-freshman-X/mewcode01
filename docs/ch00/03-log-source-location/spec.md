# MewCode 日志调用位置 Spec

## 背景

当前结构化日志需要通过调用位置直接定位业务代码。排查 MCP、dotenv 和后续 Agent 路径时需要在每条日志中看到对应项目文件及行号。

## 目标

- 每条实际写入的日志包含发起日志调用的项目相对文件路径和行号。
- 位置指向业务调用点，而不是日志模块内部。
- 不写入用户绝对路径或环境变量值。

## 功能需求

- **F1 调用点定位**：Info 和 Error 记录时捕获调用栈中直接调用日志 API 的业务代码位置。
- **F2 相对路径**：位置使用相对于项目根目录的路径和 1-based 行号，例如 `internal/mcp/manager.go:58`。
- **F3 安全降级**：调用点无法归入项目根时不记录绝对路径；可省略位置，但日志写入继续进行。
- **F4 兼容性**：现有字段、日志事件和调用接口保持兼容，no-op 记录器仍不写文件。

## 非功能需求

- **N1 并发安全**：位置捕获不破坏记录器的并发安全和单行 JSON 保证。
- **N2 性能边界**：仅在实际启用的文件记录器写入事件时执行调用栈捕获；no-op 不进行该工作。

## 不做的事

- 不记录完整调用栈、函数参数或函数名。
- 不记录工作区外绝对路径。
- 不改变消息、级别或脱敏规则。

## 验收标准

- **AC1（F1、F2）**：记录器测试调用 Info 后，JSON 事件含指向测试调用行的 `source`，且路径不含绝对项目根。
- **AC2（F3、F4）**：无法相对化的调用点不会导致日志失败；既有 Logger、MCP 和 dotenv 测试保持通过。
- **AC3（N1、N2）**：带 race detector 的并发日志测试通过；no-op 测试不创建文件。
