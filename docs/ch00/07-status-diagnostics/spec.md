# `/status` 诊断信息 Spec

## 背景

当前 `/status` 只显示当前模式和当前会话累计的输入/输出 Token。用户无法从单一、本地的状态快照确认运行工作区、会话、权限、扩展发现与后台 SubAgent 状态；第十三章 fixture 人工验收因此需要依赖额外终端命令和文件系统检查。

## 目标

- 将默认 `/status` 扩展为完整、多行的本地诊断快照。
- 让用户无需调用模型或读取敏感正文，即可确认当前会话和运行环境。
- 为后台 SubAgent 的运行状态提供安全、可观察的摘要。

## 功能需求

- F1：默认 `/status` 输出结构化多行文本，不启动 Agent Loop、不访问 Provider、不改变会话、权限规则或后台任务。
- F2：输出当前模式、工作目录、日志目录和权限模式。
- F3：输出当前会话 ID、当前会话消息数，以及累计输入/输出 Token。
- F4：输出已注册工具数量、已发现 Skill 数量、用户级与项目级记忆数量、已加载 SubAgent 定义数量。
- F5：输出运行中的后台 SubAgent 数量；每个任务显示任务 ID、名称、`running` 状态与已运行时长。没有运行中后台任务时明确显示 `0`，不显示已完成任务。
- F6：不得输出 API Key、配置文件正文、Prompt、模型/工具结果正文、日志正文、权限规则正文或后台任务结果/失败正文。
- F7：缺少可选模块（记忆、Skill、SubAgent、日志元数据）时，`/status` 仍成功输出，其对应项显示为不可用或 `0`，不 panic。

## 非功能需求

- N1：`/status` 只读取进程内快照和已加载元数据，不扫描工作区、不读取日志正文、不访问网络。
- N2：同一时刻的任务统计与任务条目来自同一安全快照；会话 Token 继续使用既有会话累计值。
- N3：并发的后台任务状态变化不能造成数据竞争、阻塞或使 `/status` 失败。
- N4：固定字段顺序、中文标签；任务列表按稳定顺序排列，时长使用便于人工阅读的格式。
- N5：保持 `/status` 为本地命令；已有模式和 Token 字段保留。

## 不做的事

- 不新增 `/status verbose`、筛选参数或交互式任务管理。
- 不提供后台任务取消、历史查询或跨进程持久化。
- 不输出单个工具名称、Skill/Agent 定义正文、记忆正文、任务结果或失败详情。
- 不在本次变更中增加模型、版本、配置路径或上下文窗口用量。
- 不修改 `/session`、`/memory`、`/skills` 等现有命令的职责。

## 验收标准

- AC1（F1、N1、N5）：空闲时执行 `/status`，立即显示多行本地反馈；不产生 Agent 任务、Provider 请求、会话消息、Token 增量或文件写入。
- AC2（F2）：反馈包含模式、当前工作目录、日志目录和权限模式；工作目录等于启动工作区。
- AC3（F3）：反馈包含当前会话 ID、消息数、累计 `tokens in/out`；新会话为零，恢复会话显示其已持久化累计值。
- AC4（F4）：反馈包含工具、Skill、用户/项目记忆、SubAgent 定义的数量；对应模块未配置时稳定显示 `0` 或不可用。
- AC5（F5、N2、N4）：无后台任务时明确显示 `后台任务：0`；启动后台子 Agent 后显示总数及其 ID、名称、`running`、耗时；任务结束后不再显示。并发读取和状态变化无数据竞争。
- AC6（F6）：在配置、用户输入、任务提示、任务结果和错误中植入唯一敏感标记后，`/status` 输出不包含这些标记。
- AC7（F7）：缺少记忆、Skill、SubAgent 或日志元数据的测试装配下，`/status` 仍正常返回基础状态信息。
