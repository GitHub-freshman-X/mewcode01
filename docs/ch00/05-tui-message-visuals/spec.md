# TUI 消息视觉层级与会话分隔 Spec

## 背景

当前 TUI 用文本标签区分“你”“MewCode”“思考”和工具事件，但所有内容共享终端默认背景，长会话中难以快速识别关键消息。切换到新会话或恢复会话时，也没有视觉边界，导致同一终端的连续会话在滚动历史中混杂。

## 目标

- 为不同类别的消息添加背景色。
- 让用户消息与模型最终答复的背景明显强于思考与工具过程。
- 在 `/session new`、`/clear`、`/session resume <id>` 后保留既有显示内容，并插入包含会话标识与标题的醒目分隔条，方便定位当前会话起点。
- 保持已有终端尺寸适配、滚动和流式输出行为。

## 功能需求

- F1：所有显示在消息区的用户消息、模型文本答复、思考内容、工具调用、工具结果、系统反馈与错误信息均以类别对应的背景色渲染；文字仍保持可读。
- F2：用户消息与模型最终答复使用比过程信息更醒目的背景；思考、工具调用与工具结果使用较弱但可辨识的背景，以形成明确层级。
- F3：流式生成期间，当前模型文本答复持续使用最终答复的背景渲染；思考内容和工具事件分别保持各自的过程样式。
- F4：命令文本和本地系统反馈继续按其现有“用户 / 助手”语义显示，并获得相应背景色。
- F5：执行 `/session new`、`/clear` 或 `/session resume <id>` 成功切换会话后，消息区不清空已有终端显示，而是在新会话内容之前显示会话分隔条；分隔条包含“会话开始”、当前会话 ID 与可用标题。
- F6：分隔条仅是 TUI 显示记录：不得写入会话历史、JSONL journal 或后续模型请求；切换会话后已有的会话、Token 统计、技能清理等语义保持不变。

## 非功能需求

- N1：保留现有 macOS、Linux、Windows 的 ANSI 终端兼容性；不引入仅特定终端支持的渲染依赖。
- N2：背景色、窄终端换行和长文本情况下，消息区域仍可滚动，流式更新与终端调整大小不应崩溃或明显阻塞。
- N3：样式应确保前景与背景对比度足够，标签、正文、错误和折叠提示均可辨认。
- N4：新渲染逻辑及会话分隔条应有无需真实模型服务的自动化测试，覆盖消息类型、流式进行中的显示与三种会话切换。
- N5：不在结构化日志、终端显示或持久化数据中额外暴露用户消息、模型内容、工具结果、密钥或其他敏感信息。

## 不做的事

- 不提供运行时主题选择、用户自定义颜色或配置文件中的配色项。
- 不改变 Markdown、代码块、表格或语法高亮的渲染方式。
- 不改变消息保存格式、会话恢复格式、模型上下文或工具结果截断规则。
- 不改变现有命令、会话切换、任务取消、权限确认及 Token 统计语义。
- 不为历史中已渲染的旧会话内容补写持久化分隔记录；分隔条只作用于当前 TUI 进程中的显示流。
- 不新增会话搜索、会话列表筛选或单独的历史浏览界面。

## 验收标准

- AC1（F1、F2）：提交普通消息后，“你”的标签和内容以用户消息背景显示；模型完成答复以另一种、同样醒目的背景显示。
- AC2（F1、F2）：包含思考、工具调用和工具结果的任务中，这些过程内容都有可区分的较弱背景，且视觉强度低于用户消息和最终答复。
- AC3（F3）：模型流式输出期间，已到达的文本持续按最终答复样式显示；流结束后样式不跳变或丢失。
- AC4（F4）：本地命令及系统反馈仍按真实交互顺序显示，并应用对应的用户或助手背景。
- AC5（F5）：依次执行 `/session new`、`/clear`、`/session resume <id>` 后，滚动历史保留此前终端显示，且每次切换位置都有包含当前会话 ID、标题的醒目“会话开始”分隔条。
- AC6（F6）：上述分隔条不出现在会话历史、JSONL 文件或下一次 Provider 请求中；会话切换后的 Token 用量和既有清理语义正确。
- AC7（N1、N2、N3、N4、N5）：相关自动化测试以及项目完整测试通过，且窄窗口下的消息区、输入区与状态栏仍可用。
