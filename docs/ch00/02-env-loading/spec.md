# MewCode `.env` 自动加载 Spec

## 背景

MewCode 的 MCP 配置可引用 `${MCP_TEST_ROOT}` 等进程环境变量，但当前不会读取项目根目录 `.env`。用户必须手动在启动 shell 中导出变量，且无法从日志得知 `.env` 与系统环境发生的变量冲突。

## 目标

- 在启动时自动读取项目根目录 `.env`，使其中变量可用于 MCP 配置和子进程。
- 系统环境变量优先于 `.env`，并对冲突输出安全日志。
- 不执行 `.env` 中的 shell 代码，不记录变量值。

## 功能需求

- **F1 项目 `.env` 发现**：MewCode 仅读取当前项目根目录的 `.env`，不搜索父目录、不读取用户目录或其他 dotenv 文件。
- **F2 安全解析**：支持空行、以 `#` 开头的注释及 `KEY=value` 声明；无效行使 `.env` 加载失败，但不得把该行正文写入日志或标准错误。
- **F3 变量优先级**：若系统环境已有同名变量，保留系统值且不覆盖；否则将 `.env` 值注入当前 MewCode 进程环境。
- **F4 启动顺序**：`.env` 在主配置读取和 MCP Server 配置展开之前完成加载，使已注入变量可被 `${VAR}` 使用，并随 stdio MCP 子进程继承。
- **F5 可观测性**：日志记录 `.env` 未找到、加载成功、加载失败和变量冲突；冲突事件仅包含变量名与状态，不包含值。
- **F6 故障隔离**：`.env` 不存在时保持原有启动行为；读取或解析失败时输出安全诊断并继续启动，既有系统环境仍可使用。

## 非功能需求

- **N1 安全性**：不得执行命令替换、source、变量展开或任何 shell 语义；日志和 stderr 不得泄露 `.env` 的变量值、整行文本或文件内容。
- **N2 兼容性**：不改变 `--config` 选择规则、主配置来源、MCP 工具命名、权限语义或未使用 `.env` 时的既有行为。
- **N3 可测试性**：可在临时项目根目录中离线验证加载、优先级、无效格式、缺失文件和日志脱敏。

## 不做的事

- 不加载多层 dotenv 文件、用户级 dotenv、父目录 dotenv 或 `.env.local`。
- 不支持 shell 语法、`export` 前缀、引号转义、变量插值或命令执行。
- 不回写调用 MewCode 的父 shell 环境。

## 验收标准

- **AC1（F1、F4）**：项目根 `.env` 中的 `MCP_TEST_ROOT` 可被随后 MCP `${MCP_TEST_ROOT}` 配置展开；父目录 `.env` 不产生影响。
- **AC2（F2、N1）**：注释、空行和合法 `KEY=value` 被正确处理；无效行产生安全失败诊断，日志和 stderr 不含变量值或原始行。
- **AC3（F3、F5）**：系统环境与 `.env` 同名时系统值被使用，日志记录变量名与冲突状态但不记录任一值。
- **AC4（F5、F6）**：`.env` 不存在、无法读取或解析失败时程序继续启动，并记录相应状态。
- **AC5（N2、N3）**：相关单元测试、MCP 竞态测试和全项目测试通过。
