# MewCode Git Worktree 文件系统隔离 Spec

## 背景

第十三章的 SubAgent 已隔离消息历史、权限批准、文件读取缓存和 Token 用量，但主 Agent 与并行运行的后台子 Agent 仍共用同一个工作目录。多个 Agent 同时读写同一文件时，可能读取到中间状态或互相覆盖修改。

Git Worktree 允许同一 Git 仓库拥有多个独立工作目录和分支，同时共享版本历史。本章在仓库内未追踪的 `.mewcode/worktrees/` 目录中管理 Worktree，使需要文件系统隔离的子 Agent 在各自目录中工作。

## 目标

- 为 MewCode 提供安全、可管理的 Git Worktree 生命周期能力。
- 让声明 `isolation: worktree` 的 SubAgent 自动在独立工作目录中执行，避免与主 Agent 或其他子 Agent 的文件修改互相干扰。
- 在不修改进程级工作目录的前提下，让工具调用显式使用当前 Worktree 目录。
- 在自动清理与后台过期清理中优先保护未提交修改和未推送提交。

## 功能需求

- **F1 Worktree 生命周期**：系统必须支持创建、查询、进入、退出和删除 Worktree。新建 Worktree 默认基于创建时的 `HEAD`，目录位于 `.mewcode/worktrees/`，并使用独立分支；删除前必须解除 Git Worktree 注册并删除关联分支。

- **F2 安全命名**：系统必须将用户或模型提供的 Worktree 名称视为不可信输入。名称总长度不得超过 64 个字符；仅允许字母、数字、点号、连字符、下划线和作为嵌套分隔符的斜杠；每个斜杠分段不得为空、不得为 `.` 或 `..`。不合法名称不得触发 Git 命令或文件系统写入。

- **F3 创建与快速恢复**：系统创建 Worktree 时必须生成可识别的分支名并执行非交互 Git 操作。若同名目录已存在且能从其 Git 指针与 HEAD 文件安全解析当前提交，系统必须直接恢复该 Worktree 信息，不得重新执行 Git 创建或检出操作。

- **F4 创建后初始化**：新建 Worktree 必须尽力补齐运行环境：复制配置指定的本地配置文件；继承或配置 Git hooks 路径；按配置将大型依赖目录链接到主工作区；根据项目的包含规则复制被 Git 忽略但运行所需的文件。可选初始化项失败时必须记录安全警告，但不得破坏已成功创建的 Worktree。

- **F5 显式工作目录与缓存隔离**：进入 Worktree 后，系统不得通过修改进程级 cwd 来切换目录。后续文件与命令工具必须从当前 Worktree 会话显式获得 cwd；文件内容、系统提示、项目指令和记忆等路径相关缓存必须以绝对路径作为键，使主工作区和不同 Worktree 的同名文件自然隔离。

- **F6 会话恢复**：系统必须持久化当前已进入的 Worktree 会话所需的最小安全元数据。进程通过恢复模式启动时，如该 Worktree 仍可用，必须恢复其显式 cwd 上下文；正常退出 Worktree 时必须清除会话记录。保留某个 Worktree 不等于持续保留已进入的会话。

- **F7 删除保护与自动清理**：删除 Worktree 前，系统必须检查未提交修改和相对于创建提交的新提交；存在任一项时，除非调用方明确确认丢弃，否则拒绝删除。隔离 SubAgent 完成后，没有改动的临时 Worktree 应自动清除；有改动的 Worktree 必须保留并向主 Agent 返回其路径和分支信息。

- **F8 过期临时目录清理**：系统必须定期检查过期的临时 Worktree。仅可处理符合系统临时命名模式、未处于当前会话、且超过保留期限的目录；删除前仍须确认无未提交修改、无新增提交且无未推送提交。任一检查失败或无法确认安全时必须保留目录。

- **F9 SubAgent Worktree 隔离**：系统必须在 SubAgent 启动前确定其 Worktree 策略，运行中不得将共享工作区任务迁移到新建 Worktree。Fork 子 Agent 必须在启动时自动创建唯一的临时 Worktree，并以该目录作为显式 cwd；调用方不得关闭此隔离。定义式子 Agent 可通过角色 frontmatter 或调用参数声明 `isolation: worktree`；声明后同样必须在启动时创建临时 Worktree。隔离任务的提示必须说明其处于独立目录，并要求将父上下文中的主工作区绝对路径转换为本地 Worktree 路径、在编辑前重新读取文件。任务完成后必须执行 F7 的自动清理规则。未声明 Worktree 隔离的前台定义式子 Agent 保持既有共享工作区行为，且不得自动转为后台。

- **F10 可观测性与用户入口**：系统必须为 Worktree 的创建、恢复、进入、退出、删除、自动清理与清理跳过记录安全元数据日志。用户必须可通过现有命令框架手动创建、查看、进入、退出和删除 Worktree，并能观察路径、分支、状态及拒绝删除的原因。

## 非功能需求

- **N1 安全性**：所有 Git 与文件系统操作必须使用已校验的路径；名称校验、路径构造、删除保护和过期清理均应失败时保守处理。Git 子进程必须禁止交互式凭据输入。日志不得记录任务 prompt、工具结果正文、密钥、请求头或原始错误载荷。

- **N2 一致性**：Worktree 中的所有文件和命令工具调用必须使用同一显式 cwd。主工作区、不同 Worktree 及其路径相关缓存不得互相污染。

- **N3 兼容性**：未使用 Worktree 的主 Agent 与前台定义式 SubAgent 必须保持第十三章既有行为。Fork 保持既有的历史继承、强制后台、工具限制及结果通知语义，仅将其文件操作目录切换至启动时创建的 Worktree。

- **N4 可靠性**：本地配置复制、依赖链接和被忽略文件复制等可选初始化失败不得留下不一致的会话状态。无法确认目录、Git 状态或变更安全性时，系统必须拒绝删除或保留目录。

- **N5 可观测性与可测试性**：生命周期关键阶段必须记录安全元数据，并能通过不访问真实模型服务的自动化测试验证：名称校验、Git 命令构造、快速恢复、显式 cwd、会话恢复、删除保护、过期清理及 Fork 的强制隔离。

## 不做的事

- 不提供 Worktree 间的合并、cherry-pick、rebase、冲突解决或回滚策略；主 Agent 使用现有 Bash 工具和 Git 命令处理。
- 不在本章实现多 Agent 团队、并行调度、跨 Agent 通信或跨 Worktree 的代码同步。
- 不支持在已经开始执行的共享工作区任务中途创建 Worktree 或迁移其文件状态。
- 不为手动创建 Worktree 提供指定基础分支的接口；均基于创建时的 `HEAD`。
- 不复制整个依赖目录；大型依赖仅按配置尽力建立链接。

## 验收标准

- **AC1（F1、F3）**：在 Git 仓库中手动创建合法名称的 Worktree 后，可观察到 `.mewcode/worktrees/` 下的独立目录、对应分支和正确的 `HEAD`；同名可恢复目录再次创建时不执行 Git 检出，且返回原目录、分支与提交信息。

- **AC2（F2、N1）**：对空名称、超长名称、`.`、`..`、空路径段、路径遍历片段和非法字符逐项调用创建操作；每项均返回可诊断校验错误，且不会创建目录、分支或执行 Git 写操作。

- **AC3（F4、N4）**：新建 Worktree 后，已配置的本地配置文件、Git hooks、依赖目录链接及被忽略运行文件按规则可用；某项可选初始化失败时，Worktree 仍可使用，输出安全警告且不遗留错误会话。

- **AC4（F5、N2）**：进入 Worktree 后，文件读取、写入和命令执行均发生在其目录；进程原始 cwd 不变；主工作区与两个 Worktree 中同名文件的读取结果和缓存互不混淆。

- **AC5（F6）**：进入 Worktree 后中断进程并以恢复模式启动，系统恢复到同一 Worktree 的显式 cwd；正常退出后，会话记录被清除，而选择保留的 Worktree 仍可在磁盘上使用。

- **AC6（F7）**：干净 Worktree 可删除；存在未提交修改或相对创建提交的新提交时，未显式确认丢弃的删除操作被拒绝并说明原因；明确确认后才执行删除。

- **AC7（F8）**：过期清理仅删除符合临时命名模式、未被当前会话使用、超过保留期且无未提交修改、无新增提交、无未推送提交的目录；任一安全检查不满足或检查失败时保留目录并记录原因。

- **AC8（F9、N3）**：启动 Fork 子 Agent 时，无论调用参数是否指定隔离，均创建唯一临时 Worktree；其工具的 cwd 指向该目录，任务提示包含隔离与路径转换说明，完成后干净目录自动清理，有改动目录保留并将路径和分支回传给主 Agent。Fork 的历史继承、强制后台和通知行为保持可观察的一致。

- **AC9（F9、N3）**：声明 `isolation: worktree` 的定义式 Agent 在启动时使用独立 Worktree；未声明隔离的前台定义式 Agent 继续在原工作区执行，且超时或 ESC 请求不会将其自动转入后台。

- **AC10（F10、N5）**：手动命令可创建、列出、进入、退出和删除 Worktree，并展示路径、分支和状态；创建、恢复、进入、退出、删除、自动清理及跳过清理均产生仅含安全元数据的日志。相关单元、集成测试及项目既有测试通过。
