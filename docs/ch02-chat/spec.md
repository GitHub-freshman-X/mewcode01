# MewCode 纯对话基础 Spec

## 背景

MewCode 是一个从零构建的命令行 AI 助手。本章建立最小可用的纯对话基础：用户从终端启动程序后进入全屏交互界面，通过可切换的模型供应商进行流式、多轮对话。

当前项目尚无实现内容，本章也将建立项目的初始结构。后续工具调用、文件操作和代码编辑能力会建立在本章的 Provider、会话与界面边界之上。

## 目标

- 提供可在 macOS、Linux 和 Windows 运行的全屏终端对话界面。
- 接收用户输入，并通过 SSE 实时呈现模型回复。
- 在当前运行期间维护多轮上下文。
- 支持 Anthropic Claude Messages API 和 OpenAI Responses API。
- 通过 YAML 配置当前协议、模型、API 根地址和认证密钥。
- 支持 Claude Extended Thinking，并在界面中流式、可折叠地呈现。
- 建立统一 Provider 边界，使后续可以增加新的模型后端。
- 本章四份设计文档存放于 `docs/ch02-chat/`；后续章节文档统一置于 `docs/` 下。

## 功能需求

- **F1 启动与配置加载**：用户启动 MewCode 后，程序读取 `~/Library/Application Support/mewcode/config.yaml`；用户可通过 `--config` 指定其他完整主配置文件。配置文件包含单套当前后端配置，四个必填核心字段为 `protocol`、`model`、`base_url`、`api_key`，并支持可选的 `max_tokens`、thinking、`agent`、`permissions` 与顶层 `mcp_servers` 配置。
- **F2 配置校验**：程序在进入对话前校验配置是否存在、YAML 是否有效、必填字段是否完整、协议是否受支持、URL 是否合法，以及 token 参数是否满足约束。校验失败时给出可定位问题的错误信息，不发起模型请求。
- **F3 全屏 TUI**：启动成功后进入全屏终端界面，至少包含可滚动的消息区域、输入区域和当前状态提示。用户可以编辑文本并提交问题。
- **F4 流式回复**：提交问题后，程序立即发起流式请求，并随着 SSE 事件到达持续更新界面，不等待整段回复完成后才显示。
- **F5 多轮对话**：在一次程序运行期间，MewCode 保存用户与模型的完整对话上下文；后续请求包含此前对话，使模型能够基于之前的内容回答。退出程序后不保存或恢复会话。
- **F6 Provider 统一行为**：界面与会话层通过统一 Provider 能力发起对话并接收规范化流事件，不直接依赖任一供应商的请求、认证或事件格式。
- **F7 Anthropic Claude 后端**：当 `protocol` 选择 Anthropic 时，程序使用配置的 API 根地址、模型与密钥调用 Messages API，按 Anthropic SSE 事件生成文本和状态更新。
- **F8 OpenAI 后端**：当 `protocol` 选择 OpenAI 时，程序使用配置的 API 根地址、模型与密钥调用 Responses API，按类型化 SSE 事件生成文本和状态更新。
- **F9 Extended Thinking**：Claude thinking 可通过可选配置启用并设置 token 预算。启用时，thinking 内容在独立区域流式呈现，生成结束后默认折叠，并可由用户展开或再次折叠。配置的 thinking 预算必须符合协议要求且小于 `max_tokens`。
- **F10 请求状态与错误反馈**：界面区分空闲、连接、思考、生成、完成、取消和失败状态。网络错误、认证失败、限流、服务端错误及无法识别的流事件不会导致界面崩溃，并向用户显示可理解的错误。
- **F11 取消与退出**：生成期间按 `Ctrl+C` 取消当前请求并保留已完成的会话；用户可以继续提问。空闲时按 `Ctrl+C` 退出。取消后的未完成模型回复不得作为完整历史发送到下一轮。
- **F12 基本界面操作**：用户可以滚动历史消息、展开或折叠 thinking 区域，并在生成完成或取消后继续输入下一条消息。

## 非功能需求

- **N1 跨平台兼容**：相同功能应在 macOS、Linux 和 Windows 的主流现代终端中运行，不依赖特定 Shell。
- **N2 响应性**：流事件到达后应及时反映到界面；网络请求和界面渲染不得阻塞用户取消操作。长回复期间界面仍可滚动和调整大小。
- **N3 稳定性**：空回复、未知 SSE 事件、连接中断、不完整事件及终端尺寸变化不得导致程序崩溃。程序应正确释放网络连接并恢复到可继续操作的状态。
- **N4 安全性**：API Key 仅从 YAML 明文读取，但不得显示在 TUI、错误信息或测试输出中。文档必须提醒用户限制配置文件权限，并避免将其提交到版本控制。
- **N5 可扩展性**：新增 Provider 时，不应要求修改 TUI 的核心对话流程；供应商特有能力通过统一事件和可选能力表达。
- **N6 可测试性**：配置加载、配置校验、会话上下文、两种协议的请求转换、SSE 事件解析、取消和错误处理应能在不调用真实模型服务的情况下自动验证。
- **N7 可维护性**：供应商协议、会话状态、界面状态和配置管理保持清晰边界，避免形成循环依赖。
- **N8 字符支持**：输入、历史上下文和流式输出完整支持 UTF-8，包括中英文和常见代码字符。
- **N9 可诊断性**：面向用户的错误应说明失败阶段和可采取的动作，同时保留底层错误原因；任何诊断信息都不得泄露 API Key。

## 不做的事

- Tool Use、函数调用或任何外部工具执行。
- 读取、搜索、创建、修改或删除本地文件。
- 代码编辑、补丁生成、Git 操作或项目索引。
- Shell 命令执行与终端子进程管理。
- 对话历史持久化、会话恢复、会话列表或跨设备同步。
- 多个供应商配置同时保存、配置档案切换或运行时切换 Provider。
- OpenAI Chat Completions API，以及其他 OpenAI-compatible 协议兼容承诺。
- 图片、音频、PDF 等多模态输入与输出。
- 登录流程、系统钥匙串、环境变量或远程密钥管理；`api_key` 仅直接写入 YAML。
- 自动重试、请求排队、并发生成或同时维护多个对话。
- 运行时修改模型参数的斜杠命令。
- Token 用量统计、费用估算及上下文自动压缩。
- Markdown 富文本渲染、代码语法高亮、主题系统和插件系统。
- 打包发布、自动更新和安装脚本；本章只要求项目可构建、测试并从源码运行。

## 验收标准

- **AC1（F1）**：默认路径存在有效配置时可直接启动；使用 `--config` 时读取指定文件；缺少四个核心字段中的任一项都会在进入 TUI 前失败并指出字段名。
- **AC2（F2）**：分别提供非法 YAML、不受支持的协议、非法 URL、无效 `max_tokens` 和无效 thinking 预算，程序均拒绝启动且不发送网络请求。
- **AC3（F3）**：使用受支持终端启动后，可观察到消息区、输入区和状态区；输入中英文问题并提交后，用户消息出现在消息区。
- **AC4（F4）**：使用分段延迟返回 SSE 的测试服务时，模型文本随事件逐步出现，而不是连接结束后一次性显示。
- **AC5（F5）**：连续提问两轮时，第二次请求包含第一轮完整的用户消息和已完成模型回复；退出重启后不包含上次会话。
- **AC6（F6）**：同一套 TUI 与会话流程可仅通过修改 `protocol` 配置分别驱动两个 Provider；界面接收到的事件类型不暴露供应商专属 SSE 结构。
- **AC7（F7）**：选择 Anthropic 后，请求发送至配置根地址对应的 Messages API 路径，并使用正确认证方式；文本增量能够完整组合为最终回复。
- **AC8（F8）**：选择 OpenAI 后，请求发送至配置根地址对应的 Responses API 路径，并使用正确认证方式；输出文本增量能够完整组合为最终回复。
- **AC9（F9）**：Claude thinking 开启后，测试流中的 thinking 增量实时出现在独立区域，完成后自动折叠，并可手动展开和折叠；关闭后请求不启用 thinking 且界面不创建 thinking 区域。
- **AC10（F10）**：模拟认证失败、限流、服务端错误、连接中断和未知 SSE 事件时，程序不崩溃，界面显示失败阶段和可理解信息，并允许用户继续操作。
- **AC11（F11）**：流式生成期间按 `Ctrl+C` 后网络请求被取消，界面进入取消状态且可继续提问；下一轮请求不包含被取消的未完成模型回复。空闲时按 `Ctrl+C` 可正常退出。
- **AC12（F12）**：消息超过可视区域后可以滚动查看；终端调整尺寸后布局仍可操作；生成结束或取消后输入区重新可用。
- **AC13（N1、N8）**：项目在 macOS、Linux 和 Windows 构建检查中通过；自动化测试验证 UTF-8 输入、上下文和分段输出不会损坏字符。
- **AC14（N2、N3）**：持续流式输出期间仍可滚动、调整尺寸和取消；空事件、不完整事件和连接异常不会引发未处理崩溃。
- **AC15（N4、N9）**：配置错误、HTTP 错误、测试日志和 TUI 文本中均不出现实际 API Key；用户文档包含明文密钥保护与版本控制警告。
- **AC16（N5、N6、N7）**：配置、会话、协议转换和 SSE 解析均有不访问真实 API 的自动化测试；两个 Provider 共用同一套上层对话入口，模块依赖检查不存在循环。
