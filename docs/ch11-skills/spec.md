# MewCode Skill System Spec

## 背景

当前 MewCode 的可复用操作流程只能由用户在每次对话中重复输入，或混入始终加载的 `MEWCODE.md`。前者容易遗漏且耗时，后者会为无关任务持续消耗上下文。第十章的 Slash Command 可以提供固定的显式快捷入口，但不能让 Agent 根据自然语言意图发现专业流程，也无法携带模板、示例、脚本和参考资料。

本章引入 Skill 技能包：将可复用的 AI 操作流程沉淀为可版本控制的 Markdown 资产，按需加载完整 SOP，并以工具白名单提升任务执行时的工具选择准确性。

## 目标

- 支持项目级和用户级 Skill 的发现、校验与覆盖。
- 通过轻量发现与按需激活，避免在普通对话中加载无关 SOP。
- 支持共享当前对话和独立执行后摘要回流两种 Skill 执行模式。
- 让 Skill 同时可被 Agent 自动发现和作为 Slash Command 显式调用。
- 用可见工具白名单收窄 Skill 任务可调用的工具集合，同时不改变既有权限边界。

## 功能需求

- **F1 Skill 发现与优先级**：系统从项目级 `.mewcode/skills/` 与用户级 `os.UserConfigDir()/mewcode/skills/` 发现单文件及目录型 Skill；同名时项目级版本覆盖用户级版本。
- **F2 Skill 定义与校验**：Skill 入口使用 YAML frontmatter 和 Markdown 正文。系统校验唯一名称、一句话说明、可见工具白名单、执行模式、独立模式历史范围与可选指定模型；正文作为发给模型的 SOP 指令，并支持参数占位符替换。
- **F3 两阶段加载**：启动和手动刷新时只收集名称、说明与可调用方式，生成供 Agent 选择的轻量 Skill 清单；不加载完整 SOP。Agent 确定需要某项 Skill 时，通过内置系统级加载工具激活并读取其完整内容。
- **F4 持续环境注入**：Skill 激活后，完整 SOP 在后续每轮模型请求的环境上下文中持续保留，且可同时激活多项 Skill。显式 Slash Command 调用时，用命令参数替换正文中的 `{{args}}`；自然语言自动加载时该占位符为空。
- **F5 工具白名单**：已激活 Skill 的白名单限制该任务对模型可见的工具。白名单引用不存在的工具时，系统在启动或刷新阶段立即失败。Skill 加载工具属于系统级能力，始终可用且不受白名单限制。
- **F6 命令集成与手动刷新**：发现成功的 Skill 自动注册为 Slash Command，支持帮助与补全。系统提供 `/skills reload` 手动重新扫描和注册 Skill；成功刷新后，新建、修改或删除的 Skill 与对应命令立即按新文件集生效。
- **F7 执行模式**：inline 模式共享当前对话，其执行结果保留在主历史中。fork 模式在独立对话中执行，完成后仅将摘要回流主对话；其历史输入可选择完整、最近或不携带主对话历史。
- **F8 对话清理与样板**：清空对话时清除已激活 Skill。系统提供 `commit`、`review`、`test` 三个内置样板 Skill，三者默认使用 inline，以保留当前对话中的需求、偏好和已确认约束；需要隔离执行的场景由自定义 Skill 显式选择 fork。目录型 Skill 可携带模板、示例、辅助脚本及参考文档，作为完整能力包按需使用。

## 非功能需求

- **N1 本地校验与诊断**：发现、frontmatter 解析、冲突检测、白名单校验及命令注册不发起模型请求；错误信息能够定位到具体 Skill 与字段。
- **N2 渐进式披露与日志安全**：轻量清单仅包含名称和说明；完整 SOP、目录资源、用户参数及模型输出不得写入结构化日志。
- **N3 可测试性**：Skill 发现、优先级覆盖、frontmatter 校验、激活、多 Skill 注入、白名单过滤、命令调用、手动刷新及清空状态均可在不启动 TUI 的条件下自动测试。
- **N4 原子刷新**：手动刷新失败时保留此前可用的 Skill 注册与激活状态；不得留下部分更新。成功时一次性切换到新发现结果。
- **N5 既有语义兼容**：inline 模式保持现有会话、权限、取消、持久化和 Token 统计语义。fork 模式与主会话隔离，主历史仅保存回流摘要。
- **N6 安全可观测性**：发现、刷新、激活、执行模式分流、白名单过滤与清除等关键边界接入既有结构化日志；日志仅含 Skill 名称、阶段、状态、模式、数量及耗时等安全元数据。
- **N7 文档与配置同步**：新增配置项或用户可见命令时，同步更新根目录 `README.md` 与 `.mewcode/config.example.yaml`。

## 不做的事

- 不实现 Skill 市场、远程下载、安装、发布、版本解析或依赖管理。
- 不实现后台文件监听或自动刷新；仅提供 `/skills reload`。
- 不实现跨进程或跨机器共享已激活的 Skill 状态。
- 不为目录资源新增专属执行接口；模板、示例、脚本和参考文档通过既有文件与命令工具按需访问。
- 不改变既有权限策略；工具白名单只能减少模型可见工具，不能提升任何工具权限。
- 不支持复杂模板语言、嵌套表达式或 `{{args}}` 之外的动态渲染语法。

## 验收标准

- **AC1（F1）**：启动时能够同时发现项目级与用户级 Skill；同名 Skill 仅使用项目级版本；单文件与目录型 Skill 均可用。
- **AC2（F2、N1）**：缺少必填元信息、名称不合法或重复、执行模式或历史范围非法时，启动或 `/skills reload` 明确失败并定位 Skill 与字段。
- **AC3（F3、N2）**：初始模型请求仅包含各 Skill 的名称和说明，不包含任何 Skill 正文或目录资源内容。
- **AC4（F3、F4）**：Agent 调用系统级加载工具后，完整 SOP 立即生效并在后续每轮模型请求中持续出现；多个已激活 Skill 全部保留。
- **AC5（F5）**：工具白名单只向模型暴露允许工具；任一白名单工具不存在时启动或刷新失败；加载 Skill 工具即使未列入白名单仍始终可用。
- **AC6（F4、F6、F8）**：`/commit`、`/review`、`/test` 可发现、补全并以 inline 模式执行；显式参数正确替换 `{{args}}`；`/skills reload` 后新增、修改、删除的 Skill 与命令按新文件集生效。
- **AC7（F6、N4）**：刷新遇到任一错误时，既有 Skill、命令和激活状态仍可继续使用；刷新成功后一次性切换到新发现结果。
- **AC8（F7、N5）**：inline Skill 使用当前对话并把结果保留在主历史；fork Skill 按完整、最近或无历史选项传入相应上下文，主历史只收到完成摘要。
- **AC9（F8）**：清空对话后，已激活 Skill 不再注入后续模型请求；已发现的 Skill 仍可再次通过命令或加载工具激活。
- **AC10（N3、N6）**：自动化测试覆盖上述行为；项目构建和既有测试通过；生命周期日志仅记录安全元数据。
