# MewCode Permission System Spec

## 背景

MewCode 已具备工具系统、Agent Loop、Plan/Do 工作流和结构化 System Prompt。当前工具层已有基础工作区路径限制和工具安全分类，但仍缺少统一的权限决策系统：危险命令无法在执行前被绝对拦截，文件路径沙箱尚未明确处理符号链接逃逸，用户无法用配置声明“哪些工具调用可以直接执行、哪些必须拒绝”，Agent Loop 也缺少人在回路的确认机制。

这会带来两类问题：一是高风险操作可能被模型直接尝试；二是低风险但未配置的操作如果被简单拒绝，会让 Agent Loop 中断，模型没有机会调整策略。本章将为 MewCode 增加一套五层防御的权限系统：危险操作黑名单、路径沙箱、可配置规则、权限模式和人在回路。权限拒绝或等待确认都必须以工具结果或明确状态反馈进入现有循环，而不是让整个 Agent 任务崩溃。

## 目标

- 在工具执行前建立统一权限门禁，所有工具调用都经过同一套权限决策。
- 对已知危险命令执行不可配置的硬拦截，避免用户或项目配置误放行高危操作。
- 对文件读写改查等路径相关操作建立基于真实路径的沙箱边界，防止相对路径和符号链接逃逸。
- 支持用户级、项目级两层 YAML 规则配置，并按项目级优先于用户级的顺序判断。
- 支持以“工具名(模式)”声明 allow 或 deny，模式可精确匹配，也可使用 glob 匹配工具参数或路径。
- 支持严格、默认、放行等权限模式，用于决定规则未明确命中时的默认处理方式。
- 在规则没有明确命中且模式要求确认时，将决策交给用户，并支持本次、本会话、永久三种放行范围。
- 权限拒绝不终止 Agent Loop；系统把拒绝原因作为结构化工具失败结果回灌给模型，使模型能调整策略继续任务。
- 本章文档存放于 `docs/ch06/`，并在文档索引中登记。

## 功能需求

- **F1 统一权限门禁**：所有工具调用在执行真实工具动作前都必须经过统一权限判断。权限判断成功才执行工具；判断拒绝时不得调用真实工具动作。
- **F2 危险操作黑名单**：执行本地命令前，系统必须用不可被配置关闭的危险操作黑名单进行检查。黑名单基于正则匹配规范化后的命令文本，命中后直接拒绝，不进入规则、权限模式或用户确认流程。
- **F3 黑名单范围**：危险操作黑名单至少覆盖破坏性删除、磁盘格式化、权限破坏、递归强制修改系统路径、进程大规模终止、明显的 fork bomb 或同类高危 shell 片段。黑名单应可由代码维护扩展，但不得通过用户、项目或本地配置放行。
- **F4 路径沙箱真实路径检查**：涉及文件路径的工具在权限判断前必须解析为真实路径。系统先把输入路径转换为绝对路径，再解析路径中已存在部分的符号链接，最后用真实路径与项目根真实路径做前缀判断。逃逸项目目录的路径必须拒绝。
- **F5 路径沙箱覆盖范围**：路径沙箱必须覆盖读文件、写文件、改文件、找文件、搜索代码，以及后续新增但声明路径参数的工具。命令工具的工作目录必须固定在项目根内；本章不要求解析命令参数中的任意路径。
- **F6 可配置规则格式**：规则以“工具名(模式)”声明匹配对象，结果只有 allow 或 deny。例如 `run_command(git *)` 表示匹配以 `git` 开头的命令文本，`read_file(docs/**)` 表示匹配文档目录下的读取路径。
- **F7 精确与 glob 匹配**：规则模式支持精确匹配和 glob 匹配。没有 glob 元字符的模式按精确匹配处理；包含 glob 元字符的模式按 glob 处理。匹配前应对路径使用统一的项目相对路径格式，对命令使用命令和参数拼接后的规范化文本。
- **F8 规则文件层级**：系统支持用户级、项目级两层 YAML 规则文件。用户级提供全局默认，项目级覆盖用户级。会话内临时放行规则覆盖所有文件规则。用户级文件固定为 `os.UserConfigDir()/mewcode/permissions.yaml`，项目级文件固定为 `<项目根>/.mewcode/permissions.yaml`。
- **F9 规则优先级**：权限判断按优先级逐层进行：危险黑名单、路径沙箱、会话级临时规则、项目级规则、用户级规则、权限模式默认行为、人在回路。更高优先级一旦命中就得到最终决策。
- **F10 规则结果语义**：规则结果只有 allow 和 deny。allow 表示该调用可直接执行；deny 表示该调用被拒绝。显式 deny 不会被放行模式覆盖，显式 allow 可在严格模式下放行；权限模式只决定未命中显式规则时的默认行为。
- **F11 权限模式**：系统支持至少三档权限模式：严格、默认、放行。严格模式下，未命中规则的所有工具调用进入用户确认；默认模式下，只读工具可默认执行，有副作用工具进入用户确认；放行模式下，未命中规则的工具调用默认执行，但仍受黑名单、沙箱和显式 deny 约束。
- **F12 人在回路确认**：当权限决策需要用户确认时，系统必须向界面发出明确的确认请求，展示工具名、匹配对象、关键参数和原因，并等待用户选择允许或拒绝。
- **F13 放行范围**：用户确认允许时，必须支持本次、本会话、永久三种范围。本次只允许当前工具调用；本会话生成会话级临时 allow 规则；永久写入项目级规则文件 `<项目根>/.mewcode/permissions.yaml`。用户拒绝时，当前工具调用返回权限失败；本章不要求持久化永久 deny。
- **F14 权限拒绝结果**：权限拒绝必须以结构化工具失败结果回灌给模型，错误类型为权限错误，并包含不泄露敏感信息的拒绝原因、规则来源或决策阶段。权限拒绝本身不得终止 Agent Loop。
- **F15 确认等待与取消**：Agent 等待用户确认期间，界面保持可取消。用户取消任务时，当前确认结束，未执行的工具不得启动，Agent 任务进入取消终态。
- **F16 多工具调度集成**：一次模型响应包含多个工具调用时，每个工具调用都必须独立经过权限判断。被拒绝的调用按失败结果写回；被允许的调用按原有只读并发、副作用串行规则执行。
- **F17 配置加载与校验**：两层规则文件的 YAML 格式必须被严格校验。无法解析、未知结果值、非法规则键或非法 glob 模式应产生可诊断错误；系统不得静默忽略错误配置后继续以更宽松权限运行。
- **F18 默认安全启动**：未找到任何规则文件时，系统仍可启动并使用默认权限模式。默认模式应保持现有只读探索顺畅，同时要求有副作用操作进入用户确认。
- **F19 规则持久化位置**：用户级规则存放于 `os.UserConfigDir()/mewcode/permissions.yaml`，项目级规则存放于 `<项目根>/.mewcode/permissions.yaml`；永久放行只写入项目级规则文件，不修改用户级规则。项目级规则文件由 `.gitignore` 忽略，避免交互放行记录意外进入版本控制。
- **F20 可观测权限事件**：权限判断、权限拒绝、用户确认请求和确认结果必须通过 Agent 事件或界面可观察状态暴露，使 TUI 能展示当前被拦截、等待确认或已放行的工具调用。
- **F21 Plan/Do 工作流兼容**：Plan Mode 仍只开放只读工具；权限系统不得扩大 Plan Mode 的工具集合。Do Mode 恢复全部工具后仍受权限系统约束。Plan Mode 临时历史隔离、计划追加和计划消费边界保持不变。

## 非功能需求

- **N1 安全优先**：危险黑名单和路径沙箱是硬边界，任何配置、模式或用户确认都不能绕过。
- **N2 可测试性**：黑名单匹配、真实路径沙箱、规则层级、权限模式、人在回路、拒绝回灌和 Agent Loop 继续执行都必须能在不访问真实模型服务的情况下自动测试。
- **N3 确定性**：相同工具调用、相同项目根、相同规则文件、相同权限模式和相同会话临时规则下，权限决策结果必须稳定一致。
- **N4 可诊断性**：权限拒绝和配置错误应说明发生在哪个决策阶段、匹配了哪类规则或配置问题是什么，同时避免泄露 API Key、完整环境变量或不必要的绝对路径。
- **N5 最小权限默认**：默认配置不得直接放行有副作用工具；用户必须通过明确规则、权限模式或确认动作扩大权限。
- **N6 跨平台路径兼容**：路径解析和前缀判断应兼容 macOS、Linux 和 Windows 的路径分隔符、大小写差异和符号链接行为；平台差异应有测试或明确错误。
- **N7 配置可审阅性**：规则 YAML 应结构简单、结果值有限、匹配字符串可读，便于用户审查项目权限意图。
- **N8 Agent Loop 稳定性**：权限系统不得引入未处理 panic、半轮历史、工具结果错配或终态重复；权限失败应像普通工具失败一样被模型看到。
- **N9 兼容性**：现有配置文件不增加权限配置时仍可加载；现有第 2 章到第 5 章自动测试应继续通过或只因新增确认默认行为而进行有意更新。
- **N10 扩展性**：新增工具时应能声明自己的权限匹配对象和路径参数，不需要把每个工具的权限逻辑硬编码到 Agent Loop。

## 不做的事

- 不做网络请求限制、域名白名单、代理策略或外部服务访问控制。
- 不做 CPU、内存、磁盘、进程数或运行时长以外的资源配额系统。
- 不做持久化审计日志、审计查询、报表或安全事件数据库。
- 不做容器、虚拟机、操作系统级沙箱或系统调用隔离。
- 不解析命令参数中的任意文件路径，也不保证命令内部不会访问项目外路径；本章只固定命令工作目录并执行危险命令黑名单。
- 不做基于 Git 状态的自动保护，例如禁止修改未跟踪文件、禁止覆盖用户改动或自动回滚。
- 不做远程策略同步、团队权限中心、签名规则或配置加密。
- 不做永久 deny 的交互写入；拒绝只影响当前工具调用，显式 deny 仍通过规则文件配置。
- 不做规则编辑 UI；本章只要求确认交互和必要的状态展示。
- 不改变 Provider 请求协议、模型工具调用协议或 System Prompt 缓存策略。

## 验收标准

- **AC1（F1、F14、N8）**：模拟一个会被权限拒绝的工具调用时，真实工具动作未执行，模型历史收到结构化权限失败结果，Agent Loop 继续下一轮而不是失败终止。
- **AC2（F2、F3、N1）**：执行命令匹配危险黑名单时，即使存在显式 allow 规则、放行模式或用户试图确认允许，系统仍拒绝该调用，且真实命令未启动。
- **AC3（F4、F5、N6）**：通过相对路径、绝对路径和指向项目外的符号链接访问项目外文件时，路径相关工具均返回权限失败；访问项目内真实路径时可继续进入后续规则判断。
- **AC4（F6、F7）**：配置 `run_command(git *)`、`read_file(docs/**)` 和一个精确文件规则后，对应命令文本和路径能正确匹配；不匹配的相似字符串不会误命中精确规则。
- **AC5（F8、F9、F10）**：同一调用同时被用户级 allow、项目级 deny 和会话级 deny 覆盖时，最终采用会话级 deny；移除会话级规则后采用项目级 deny；显式规则优先于权限模式默认行为。
- **AC6（F11、F18、N5）**：未配置规则时，严格模式下读文件和写文件都请求用户确认；默认模式下读文件直接执行、写文件请求确认；放行模式下普通写文件直接执行，但仍无法绕过黑名单和路径沙箱。
- **AC7（F12、F13、F15、F20）**：未命中规则且需要确认的工具调用会向 TUI 发出确认请求；用户选择本次允许后只执行当前调用；选择本会话允许后相同调用在会话内不再询问；取消确认会取消 Agent 任务且不启动工具。
- **AC8（F13、F19）**：用户选择永久允许后，项目级规则文件 `<项目根>/.mewcode/permissions.yaml` 新增对应 allow 规则；重新启动后相同调用可由项目级规则命中；用户级规则文件未被修改。
- **AC9（F14、F16）**：一次响应包含“允许的读工具、拒绝的写工具、允许的读工具”时，两个允许的读工具仍按原有调度规则执行，拒绝的写工具以权限失败结果按原始顺序写回模型。
- **AC10（F17、N4）**：规则文件包含非法 YAML、未知结果值或非法规则键时，系统启动或任务准备阶段返回可诊断错误，不以更宽松权限继续运行。
- **AC11（F20）**：权限判断命中 allow、命中 deny、等待确认、确认允许和确认拒绝都能通过事件记录或界面状态观察到工具名、决策阶段和安全摘要。
- **AC12（F21）**：Plan Mode 请求仍只包含只读工具；Do Mode 请求恢复全部工具但执行时受权限系统约束；现有计划追加、计划消费和 Plan Mode 历史隔离测试继续通过。
- **AC13（N2、N3、N10）**：使用脚本化工具和脚本化确认器运行同一权限场景两次，决策结果、工具执行次数和写回结果顺序完全一致；新增测试工具可通过声明匹配对象接入权限判断。
- **AC14（N9）**：不提供任何权限配置的新旧配置文件均可加载；第 2 章到第 5 章既有自动测试继续通过，或新增确认默认行为的测试更新有明确原因。
