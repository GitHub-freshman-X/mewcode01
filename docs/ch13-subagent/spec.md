# MewCode SubAgent 子任务分发 Spec

## 背景

当前 MewCode 的主 Agent 在单一会话和执行循环中处理所有工作。长时间的探索、修改、验证或多个无关任务会把中间工具结果和推理过程留在主上下文中，造成上下文污染、Token 消耗增加，并阻塞用户交互。

第 12 章 Hook 已为子 Agent 动作保留运行时接入点，但尚不能实际创建和运行子 Agent。本章引入 SubAgent：主 Agent 可将子任务委派给独立的执行单元，子任务完成后以结果通知回传主对话。

## 目标

- 让主 Agent 能以稳定的统一工具委派独立子任务。
- 支持预定义角色的定义式子 Agent，以及继承父对话的 Fork 子 Agent。
- 隔离子任务的运行时状态和权限，同时复用必要基础设施。
- 支持前台、自动后台、手动后台和 Fork 强制后台执行，并在 TUI 中提供可观察的状态和通知。
- 通过工具能力边界防止递归派生、后台越权和无限嵌套。

## 功能需求

- **F1 统一委派工具**：系统必须提供固定名称且 schema 稳定的 Agent 工具。该工具接受任务、描述、可选角色类型、模型覆盖、后台标志、任务名和隔离选项；指定角色类型时走定义式路径，省略角色类型时走 Fork 路径。
- **F1a Fork 参数兼容**：除省略角色类型外，统一委派工具还必须将角色类型值为 `fork` 的调用识别为 Fork 创建；两种写法的后台强制执行、历史继承、递归限制和结果语义必须一致。`fork` 是保留值，不能用于定义式角色名。
- **F2 Agent 定义与加载**：角色定义必须由 YAML frontmatter 和 Markdown 正文构成。frontmatter 支持角色名、用途说明、工具白名单、工具黑名单、模型、最大轮次和权限模式；正文定义子 Agent 的身份、职责和工作风格，并在整个子 Agent 生命周期中作为系统提示。系统从项目级、用户级、内置级和插件级来源加载定义；同名定义按项目级、用户级、内置级、插件级的顺序覆盖。项目级目录为 `<项目根>/.mewcode/agents/`，用户级目录为当前平台标准用户配置目录下的 `mewcode/agents/`。
- **F3 内置角色**：系统默认提供 `Explore`、`Plan` 和 `general-purpose` 三种内置定义。系统仅在 `enableVerificationAgent` 配置为 true 时提供 `Verification` 定义。
- **F4 定义式创建**：定义式子 Agent 必须从空白对话开始，以角色定义正文和任务启动；它使用角色定义或调用参数所选择的模型、轮次、权限模式和工具边界。
- **F5 Fork 创建**：Fork 子 Agent 必须继承父 Agent 已渲染的系统提示、完整对话历史和工具集；对历史末尾未完成的工具调用补齐格式合法的占位工具结果，再追加 Fork 约束和子任务。Fork 子 Agent 不得再次 Fork。
- **F6 隔离与共享**：每个子 Agent 必须独立维护消息历史、权限批准记录、文件读取缓存和 Token 用量。LLM 客户端、Hook 引擎和当前工作区文件系统可以共享；文件系统修改仍经既有工具、权限和 Hook 边界处理。
- **F7 工具过滤**：定义式子 Agent 的实际工具集必须依次应用全局禁止规则、角色附加限制、角色黑名单和角色白名单。后台 Agent 必须额外应用固定基础工具白名单，且该白名单不包含创建子 Agent 的能力；后台 Agent 不得通过定义配置放宽该限制。
- **F8 跑到底执行**：子 Agent 接收任务后必须持续执行模型与工具循环，直到模型返回不含工具调用的文本、达到最大轮次、被取消或发生不可恢复失败。系统必须返回最终文本或可诊断失败摘要，并归集该子 Agent 的实际 Token 用量。
- **F9 后台任务管理**：系统必须管理后台任务的唯一标识、名称、状态、最终结果、起止时间、取消能力、工具调用计数和 Token 用量。任务可通过调用时显式指定进入后台；前台子 Agent 运行满 120 秒时自动转入后台；用户在 TUI 中按 ESC 时可将当前前台子 Agent 转入后台。Fork 子 Agent 必须无条件以后台方式运行。
- **F10 回传与主对话**：后台任务完成、失败或取消后，系统必须向主对话追加结构化任务通知。主 Agent 在后台任务运行期间必须能继续接收并处理后续用户输入。
- **F11 TUI 交互**：TUI 必须显示前台子 Agent 的运行进度；支持 ESC 将其转入后台；显示后台任务的状态变化以及完成、失败或取消通知，且上述显示不得阻塞主会话输入。

## ESC 提示与后台终态通知修复需求

### 功能需求

- **F12（ESC 提示时序）**：用户按 ESC 成功将前台子 Agent 转为后台后，系统提示必须显示在该主回合之后、任意后续对话回合之前；不得永久落在聊天末尾。
- **F13（终态通知展示）**：后台子 Agent 进入 `completed`、`failed` 或 `cancelled` 后，TUI 必须显示包含任务名称、终态和安全摘要的系统通知。
- **F14（通知监听生命周期）**：TUI 初始化后即开始监听子 Agent 通知；每次收到通知后必须继续监听后续通知。任务在主会话空闲或正在处理后续输入时完成，都不得遗漏终态展示。
- **F15（前台期限与接管生命周期）**：前台 Agent 工具调用不得受通用 30 秒工具期限截断，必须允许任务运行至既有 120 秒自动后台阈值；ESC 或自动接管后，同一任务必须脱离原前台调用的 deadline 与取消信号并继续执行。未接管的前台任务仍必须在主任务被 `Ctrl+C` 取消时结束。
- **F16（终态日志）**：每个子 Agent 任务进入 `completed`、`failed` 或 `cancelled` 时，系统必须写入且仅写入一条对应终态日志。
- **F17（终态覆盖范围）**：定义式、Fork、前台、显式后台、ESC 接管和自动后台化必须复用相同的终态日志语义。
- **F18（终态安全元数据）**：终态日志必须包含任务状态、创建模式、后台标记、模型、工具调用数、Token 用量和耗时；失败或取消时可包含既有安全失败摘要。

### 非功能需求

- **N9（不阻塞与时序稳定）**：监听和展示通知不得阻塞输入框、主 Agent 执行或后台任务执行；提示位置以发生时的会话边界为准，后续消息提交后不得改变其相对顺序。
- **N10（安全与兼容）**：终态提示仅展示既有安全摘要，不新增 prompt、工具结果正文、密钥或原始错误载荷；保留现有任务状态、ESC 接管、`Ctrl+C` 取消，以及向下一次模型请求注入结构化任务通知的行为。
- **N11（可回归验证）**：自动化测试必须覆盖 ESC 提示重排、首次终态通知消费和连续多通知消费。
- **N12（期限边界）**：仅 Agent 工具的前台生命周期可绕过通用工具的 30 秒期限；其他工具继续遵守既有期限，后台化不得重复启动子任务或丢失其终态。
- **N13（终态日志安全）**：终态日志不得包含 prompt、模型消息、工具结果正文、密钥、请求头或原始错误载荷。
- **N14（终态日志不阻塞）**：终态日志写入不得阻塞任务终态、通知发布、前台返回或后台执行。

### 不做的事

- 不修改后台任务的创建、执行、取消或状态机语义。
- 不将 TUI 系统提示持久化到会话历史，或发送给模型。
- 不新增后台任务查询、持久化、跨进程恢复或通知中心。
- 不改变终态通知的安全摘要内容规则。
- 不处理本次范围外的普通系统提示排序问题。
- 不修改 Provider 请求日志；该问题独立处理。
- 不改变 TaskManager 状态迁移、任务通知、TUI 展示、会话持久化，也不新增任务查询、持久化或跨进程恢复。

### 验收标准

- **AC12（F12）**：前台子 Agent 运行时按 ESC，主回合完成后再提交下一轮对话；“子 Agent 已转入后台。”显示在原主回合之后、下一轮用户消息之前。
- **AC13（F13、F14）**：TUI 初始化后发布一个后台任务终态通知；视图显示其任务名、`completed`、`failed` 或 `cancelled` 状态及安全摘要。
- **AC14（F14）**：依次发布多个后台任务终态通知；每项均只显示一次，且顺序与接收顺序一致。
- **AC15（N9、N10、N11）**：收到通知后输入框仍可用；ESC 接管、`Ctrl+C` 取消和主 Agent 的下一请求任务通知注入仍保持现有行为；新增回归测试不允许终态提示包含不安全正文，相关 TUI 与 Agent 测试通过。
- **AC16（F15、N12）**：模拟超过 30 秒但未到自动后台阈值的前台 Agent 调用不会被通用工具期限取消；ESC 或自动接管后的同一任务在原前台调用 context 取消后仍可完成；未接管的前台任务在父 context 取消后进入 cancelled；非 Agent 工具的 30 秒期限保持不变。
- **AC17（F16、F18、N13）**：完成、失败、取消三类任务各产生一条对应终态日志；日志含状态、模式、后台标记、模型、工具调用数、Token 用量和耗时，且不含 prompt、模型消息、工具结果正文、密钥、请求头或原始错误载荷。
- **AC18（F17）**：前台、显式后台、Fork、ESC 接管和自动后台化的任务终态均采用同一记录语义，每个任务终态仅记录一次。
- **AC19（N14）**：终态日志写入后，任务通知、前台返回及后台执行保持既有非阻塞行为。

## 非功能需求

- **N1 安全性**：子 Agent 不得绕过已有权限、工作区沙箱或 Hook。定义式、Fork 和后台路径均必须在能力层阻止未允许的工具和递归派生。
- **N2 隔离性**：一个子 Agent 的消息、权限批准、读缓存、任务状态和 Token 用量不得影响父 Agent 或其他子 Agent。
- **N3 缓存兼容性**：Fork 必须尽可能保持父 Agent 已渲染系统提示和对话历史前缀稳定，以兼容 Provider 的 prompt cache。实际命中与否由 Provider 决定；系统只记录 Provider 返回的缓存 Token 用量，不承诺必然命中。
- **N4 可靠性**：子任务崩溃、超时、取消或后台失败不得终止主 Agent。主 Agent 接收的状态通知必须可诊断且不含敏感正文。
- **N5 可观测性**：关键阶段必须记录创建模式、状态、工具调用计数、轮次、Token 用量、耗时、模型和过滤结果等安全元数据。日志不得记录 prompt、工具结果正文、密钥、请求头或未经脱敏的错误载荷。
- **N6 跨平台与兼容性**：用户级定义必须由当前平台的标准用户配置目录定位，不能依赖 Unix 专有的 home 目录约定。未配置额外定义时，既有主 Agent 行为和工具列表必须保持兼容。
- **N7 可测试性**：定义加载和覆盖、两种创建路径、状态隔离、工具过滤、终止条件、任务状态迁移、三种后台入口、Fork 强制后台、通知注入和 TUI ESC 流程必须能在不访问真实模型服务的自动化测试中验证。
- **N8 兼容性**：现有省略角色类型的 Fork 行为必须保持不变；`fork` 保留值不得被误解析为同名定义式角色。

## 不做的事

- 不实现 Git Worktree 或其他文件系统隔离；父子 Agent 默认共用当前工作区。
- 不实现平等协作、多 Agent 群聊、团队编排或 Agent 间自由消息通信；仅支持主 Agent 委派、子 Agent 回报。
- 不持久化后台任务，不支持跨进程或跨会话恢复、查询或取消任务。
- 不承诺或伪造 Provider prompt cache 命中；仅保持可复用前缀并记录实际返回用量。
- 不实现远程定义下载、图形化编辑器、定义市场、插件安装管理；插件级来源仅保留运行时注册接入点。
- 不支持 Fork 子 Agent 再 Fork；不允许任何后台任务创建子 Agent。
- 不实现 Worktree 隔离选项的实际语义；若 Agent 工具保留该选项，必须明确返回“本章未支持”，不得静默降级。

## 验收标准

- **AC1（F1）**：主 Agent 的工具 schema 始终仅包含一个 Agent 工具；调用时指定内置或自定义类型创建定义式子 Agent，类型为空创建 Fork 子 Agent。
- **AC1a（F1a）**：省略角色类型和角色类型为 `fork` 的调用均创建强制后台 Fork；它们继承相同父历史并得到相同的递归限制。任一定义来源声明名称为 `fork` 时必须产生可诊断错误。
- **AC2（F2）**：项目级、用户级、内置级和注入的插件级定义均可加载；同名角色按项目、用户、内置、插件顺序覆盖。非法 frontmatter、重复来源或无效模型、权限模式、轮次产生可诊断错误。
- **AC3（F3）**：默认加载 `Explore`、`Plan`、`general-purpose`；仅在 `enableVerificationAgent: true` 时加载 `Verification`，且示例配置和 README 说明实际默认值及行为。
- **AC4（F4、F5、F6）**：定义式子 Agent 的首个请求只包含固定角色提示和任务，不包含父历史；Fork 的首个请求保留父系统提示和历史前缀，并为未完成工具调用补齐合法占位结果。两种模式的消息、权限、读缓存和 Token 用量互不影响。
- **AC5（F7）**：定义式工具集正确应用全局禁止、角色限制、白名单和黑名单；后台白名单进一步限制能力。Fork 不可再次 Fork；任何后台 Agent 均无法创建子 Agent。
- **AC6（F8）**：子 Agent 在纯文本完成、轮次上限、取消或错误时进入对应终态，返回最终文本或明确失败摘要，并记录实际 Token 用量。
- **AC7（F9）**：显式后台、前台运行满 120 秒自动后台、TUI 按 ESC 手动转后台均创建或接管同一任务；Fork 始终后台。任务查询可观察 ID、名称、状态、耗时、用量和完成结果。
- **AC8（F10）**：后台任务完成、失败或取消后，主对话收到结构化通知；主 Agent 在任务运行期间仍可继续接收和处理用户输入。
- **AC9（F11）**：TUI 可观察前台子 Agent 进度、ESC 转后台后的状态变化及后台终态通知，不阻塞主会话后续输入。
- **AC10（N1、N4、N5）**：子任务失败、超时或取消不终止主 Agent；日志只包含安全元数据，不包含 prompt、工具结果正文、密钥、请求头或原始错误载荷。
- **AC11（N3、N6、N7）**：自动测试验证 Fork 请求前缀保持、Provider 返回缓存 Token 的正确归集、跨平台用户路径、未启用或未配置定义时的兼容性，以及关键状态和交互流程。
