# MewCode 跨会话记忆与会话持久化 Spec

## 背景

第八章已解决单个会话内的上下文压缩与 Token 管理，但 MewCode 退出后仅存于内存中的会话历史会丢失；新启动的会话也不了解项目约束、用户偏好与此前积累的项目知识。现有 Agent Loop 已具备统一的 Provider 调用边界、会话历史对象与任务模式，可作为本章持久化和记忆注入的接入点。

## 目标

- 启动新会话时，自动加载用户级与项目级指令、自动记忆索引，使 Agent 在首轮请求前具备可持续的项目知识和用户偏好。
- 将会话历史以可增量写入、可容错恢复的本地格式保存；默认启动新会话，并为后续章节的会话恢复命令提供底层能力。
- 在普通聊天、`/do` 与 `/plan` 正常结束后，异步提取可长期复用的信息，按用户级与项目级分别保存。
- 定期治理自动记忆，控制索引大小并清除重复或过时信息。

## 功能需求

- **F1 指令文件加载**：每个新会话启动前，系统依次读取用户级目录 `os.UserConfigDir()/mewcode/MEWCODE.md` 与项目级目录 `<项目根>/.mewcode/MEWCODE.md`。存在的文件按“用户级在前、项目级在后”以分隔线拼接并注入首轮请求，使项目规则在位置上更靠后。
- **F2 指令模块化与安全**：指令文件支持以单独一行 `@相对路径` 引入项目内其他文本文件。系统递归展开引用，最大嵌套深度为 5；通过已访问路径集合阻止循环或重复展开；拒绝解析后跳出项目根目录的路径。引用文件不存在或被拦截时，保留一条安全的说明并继续加载其余内容。
- **F3 会话追加存档**：系统为每个新会话生成 `YYYYMMDD-HHMMSS-xxxx` 格式的唯一标识，并在 `<项目根>/.mewcode/sessions/` 创建对应 JSONL 文件。每一轮用户消息、模型回复、工具调用及工具结果都应在写入内存历史时追加持久化；文件记录采用 Provider 无关的内部表示。
- **F4 会话扫描与容错恢复**：系统可通过扫描会话 JSONL 文件获得会话 ID、创建时间、最后活跃时间、标题和消息数，不维护独立元信息文件。恢复时跳过损坏行；发现未配对的工具调用时，从该调用开始截断后续不完整历史；恢复后先按第八章规则检查并在必要时压缩历史；距上次活跃超过 24 小时时，向恢复后的历史加入时间跨度提示。
- **F5 会话保留与清理**：系统保留默认启动新会话的行为，并提供给后续 `/session` 命令调用的创建、列表、恢复与删除能力。启动时清理最后活跃时间超过 30 天的会话文件。
- **F6 自动记忆存储**：系统将用户偏好与纠正反馈保存至 `os.UserConfigDir()/mewcode/memory/`，将项目知识与参考资料保存至 `<项目根>/.mewcode/memory/`。每条记忆为包含名称、描述和类别元数据的独立 Markdown 文件；每个目录分别维护 `MEMORY.md` 索引。
- **F7 记忆提取与去重**：普通聊天、`/do` 与 `/plan` 在模型给出不含工具调用的最终回复后，系统异步分析本轮对话；按用户偏好、纠正反馈、项目知识、参考资料四类，创建、更新或删除记忆，并同步更新索引。重复或语义相同的内容由提取 LLM 判断，不新增重复记忆。无长期价值信息时不产生文件修改。
- **F8 记忆注入**：每个新会话的首轮请求前，系统加载用户级与项目级 `MEMORY.md` 索引，并与指令文件一同注入上下文。每份索引最多注入前 200 行且不超过 25KB；达到任一上限时截断并说明内容未完全载入。
- **F9 记忆治理**：系统在任务正常结束后进行低成本惰性检查；当记忆目录存在、距离上次整理至少 24 小时、扫描节流允许、累计会话数不少于 5 且成功取得并发锁时，后台整理重复、过时或矛盾的记忆及索引。整理不阻塞用户任务，并限制其文件写入范围为记忆目录。

## 非功能需求

- **N1 崩溃容错**：会话记录采用逐行追加写入；进程中断时，已经写完的记录必须可恢复，最多忽略最后一条不完整记录。写入顺序应先完成持久化，再更新内存会话状态。
- **N2 Provider 中立**：持久化的会话工具调用与工具结果不得依赖 Anthropic、OpenAI 或其他特定协议；恢复时由现有 Provider 适配层转换为当前模型需要的格式。
- **N3 启动与交互性能**：新会话的指令和索引加载只读取必要文件；记忆提取和治理均在后台执行，不阻塞最终回复、下一轮输入或 `/plan` 的结果展示。
- **N4 数据隔离与路径安全**：项目级数据只能位于当前项目的 `.mewcode/` 下，用户级数据只能位于用户配置目录的 `mewcode/` 下。`@` 引用不得读取项目根目录以外的文件；记忆治理不得写入记忆目录以外的路径。
- **N5 安全可观测性**：关键生命周期必须接入既有 `internal/logging`，记录阶段、状态、数量、耗时、大小和类型等安全元数据；不得记录指令正文、会话正文、记忆正文、工具结果、密钥或未经脱敏的错误载荷。
- **N6 配置兼容性**：本章新增或变更的可配置项必须经过现有配置加载与校验，并同步更新 `.mewcode/config.example.yaml`。固定目录约定与 JSONL 格式不作为可配置项。
- **N7 可测试性**：指令优先级、引用安全、JSONL 容错恢复、过期清理、索引上限、自动提取调度和治理锁均可通过自动化测试验证，且测试不访问真实模型服务或用户实际目录。

## 不做的事

- 不实现向量数据库、嵌入生成、RAG、语义检索或基于相似度算法的记忆检索。
- 不实现团队记忆共享、远程同步、云端备份、多设备合并或权限协作。
- 不在本章新增 `/session`、`/clear`、`/status` 等 Slash Command，也不增加会话选择 TUI；第十章负责提供用户入口。
- 不自动恢复最近会话；MewCode 每次启动都创建新会话。
- 不将全部历史正文或全部记忆正文直接注入每次请求；只注入指定层级的项目指令与受限索引。
- 不保证自动提取或治理在应用退出前完成，不因后台记忆任务失败而让已完成的主任务变为失败。
- 不在本章把记忆治理扩展为通用子 Agent 框架；仅实现记忆范围内的受限后台整理。

## 验收标准

- **AC1（F1、F8）**：用户级和项目级指令文件同时存在时，新会话的首轮请求包含两者，且用户级内容位于项目级内容之前；用户级与项目级记忆索引亦会被加载。缺失任一文件时，其他可用文件仍正常注入。
- **AC2（F2、N4）**：有效的嵌套 `@` 引用能被展开；循环引用仅展开一次；第 5 层后的引用不再继续展开；项目根外路径与不存在的文件被安全标记，且不会中断其余指令加载。
- **AC3（F3、N1、N2）**：完成包含工具调用的一轮任务后，对应 JSONL 文件包含可重建的用户、助手、工具调用和工具结果记录；工具结果使用与 Provider 无关的表示；模拟在最后一行中断后，前面的完整记录仍可恢复。
- **AC4（F4）**：含坏行的会话恢复时跳过坏行继续读取；未配对工具调用后的记录不进入恢复历史；恢复的超长历史在下一次模型调用前按第八章策略压缩；超过 24 小时未活跃的会话会包含时间跨度提醒。
- **AC5（F5）**：创建的会话 ID 满足 `YYYYMMDD-HHMMSS-xxxx` 格式且同秒创建不冲突；扫描 JSONL 可获得列表所需元信息；启动清理后，超过 30 天的会话被移除，未过期会话保持可恢复。
- **AC6（F6、F7）**：一次正常完成的普通聊天、`/do` 或 `/plan` 任务可以异步创建或更新正确层级、正确类别且包含元数据的记忆文件和 `MEMORY.md` 索引；模型判定无长期价值信息时不修改文件；相同语义信息不产生重复笔记。
- **AC7（F8）**：`MEMORY.md` 超过 200 行或 25KB 时，首轮请求仅包含限制内的索引内容，并带有截断提示。
- **AC8（F9、N3、N4）**：满足时间、扫描节流、会话数量和锁条件时触发后台治理；治理合并重复项、移除过时索引项且仅修改记忆目录；锁被有效持有时不会并发执行第二次整理；主任务仍可立即完成和接受下一轮输入。
- **AC9（N5、N6、N7）**：自动化测试覆盖上述关键路径且不访问真实模型或用户目录；运行日志包含安全元数据而不含敏感正文；新增配置项（如有）可由示例配置展示并通过校验。
