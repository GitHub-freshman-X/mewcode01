# MewCode 上下文管理 Spec

## 背景

MewCode 的 Agent Loop 会在每次模型请求时发送当前会话历史。历史会累积用户消息、模型回复、工具调用和工具结果；其中工具结果通常占用最多 Token。现有系统仅汇总 Provider 返回的用量，未限制单条工具结果体积，也未在历史接近模型上下文窗口上限时压缩，因此长时间任务可能因上下文超限而失败。

## 目标

- 通过轻量预防和重量兜底两层策略，使普通执行、`/do` 与 `/plan` 能在有限 Token 预算内持续工作。
- 优先保留用户的原始表达、近期执行上下文和可重新读取的完整工具结果。
- 支持自动、手动、强制和紧急压缩，并在摘要失败时避免无限重试。
- 让窗口大小与各类阈值可配置，默认采用本章参考文档中的 200K、20K、13K 与 3K 数值。

## 功能需求

- **F1 工具结果持久化**：工具结果在写入任一历史前，系统应检查单个结果大小；超过配置阈值时，将完整内容保存到当前会话专属的本地结果文件，并以包含原始大小、文件路径和固定长度前缀预览的引用替换历史内容。读取该持久化文件所返回的内容不得再次被持久化替换。创建会话及创建结果存储对象不得创建结果目录；首次需要保存大结果时才创建 `.mewcode/context/<持久会话 ID>/tool-results/`。恢复会话使用被恢复会话的同一持久 ID，能够读取此前结果，并将后续大结果继续写入同一目录。
- **F2 消息聚合预算**：同一条历史消息包含的多个工具结果累计超过配置预算时，系统按结果大小从大到小依次持久化替换，直至该消息落入预算；未超过预算的结果保留原文。
- **F3 写入终态**：第一层替换必须在结果进入历史前完成。已提交历史不因后续轮次重新改写，以保持模型请求前缀稳定；完整结果仅通过持久化文件按需重新读取。
- **F4 Token 估算**：系统应锚定最近一次成功模型请求的真实输入用量，仅对该锚点之后新增的上下文按统一字符近似规则估算。每次模型请求前均可获得当前输入上下文的估算 Token 数。
- **F5 自动压缩**：每次模型请求前，在第一层处理完成后，系统应根据配置窗口大小、摘要输出预留和自动安全余量判断是否压缩。自动阈值为“窗口大小减摘要输出预留再减自动安全余量”；估算用量超过该阈值时，系统自动执行摘要压缩。
- **F6 手动压缩**：系统提供 `/compact` 命令。在没有活动 Agent 任务时，用户执行该命令应无条件触发一次摘要压缩，不受当前估算用量限制；手动触发使用配置的手动安全余量作为压缩后目标预算。
- **F7 结构化摘要**：摘要请求应要求模型依次产生主要请求与意图、关键技术概念、文件和代码、错误和修复、问题解决过程、所有用户原话、待办任务、当前工作、可能的下一步九个部分。用户原话应尽量逐字保留；空间不足时优先保留最新且带有明确约束的原话。
- **F8 摘要调用约束**：摘要调用应明确禁止调用工具，并只接收文本输出。模型可先输出分析草稿再输出正式摘要；草稿不进入压缩后的历史，只有正式摘要被保留。
- **F9 历史重建**：压缩后，系统应以一条边界消息、结构化摘要和近期原文重建历史。边界消息必须提示模型：摘要未包含的文件细节、代码或错误信息需要重新读取，不得据摘要臆测。近期原文从历史末尾按约 10K Token 或至少 5 条消息保留，且不得拆开模型工具调用与对应工具结果的配对。
- **F10 适用范围与隔离**：两层压缩适用于普通执行、`/do` 和 `/plan` 的多轮历史。普通执行与 `/do` 压缩共享会话历史；`/plan` 仅压缩本次规划任务的临时历史，任务结束后不得影响共享历史。
- **F11 熔断与恢复**：自动摘要连续失败三次后，系统应暂停后续自动触发，避免死循环。用户仍可通过 `/compact` 手动重试；手动压缩成功后应清零失败计数并恢复自动触发资格。
- **F12 强制与紧急压缩**：当估算用量越过“窗口大小减摘要输出预留再减手动安全余量”时，系统应执行强制压缩，不受自动熔断影响。正常模型请求仍返回上下文超限错误时，系统应执行一次紧急压缩并仅重试原请求一次。
- **F13 配置与反馈**：系统应支持配置窗口大小、摘要输出预留、自动安全余量、手动安全余量，以及第一层的单结果与消息聚合预算。`/compact` 和各类自动压缩应通过现有 Agent 事件让界面可展示触发原因、执行状态、压缩前后估算 Token 和失败信息。

## 非功能需求

- **N1 默认值与校验**：默认窗口大小为 200,000 Token，摘要输出预留为 20,000 Token，自动安全余量为 13,000 Token，手动安全余量为 3,000 Token。配置必须为非负，且窗口大小必须大于摘要输出预留与相应安全余量之和。
- **N2 Provider 中立**：上下文管理只依赖既有统一 Provider 边界；摘要使用当前任务的 Provider，不依赖特定厂商 API。
- **N3 提示词稳定性**：不重写已提交的未压缩历史；压缩只在触发时替换早期历史，避免无意义地降低 Prompt Cache 命中。
- **N4 可观测与可测试**：所有压缩路径、熔断状态、持久化引用与配置边界均可在不访问真实模型服务的自动化测试中观察和验证。
- **N5 资源与安全**：持久化内容保存在会话专属目录，目录权限为 `0700`、结果文件权限为 `0600`；未产生大结果的会话不得留下空的 context 目录。没有工作区、没有持久会话 ID 或目录创建失败时，工具结果保留原文且任务继续安全运行。任务结束、取消、摘要失败或消费者退出时不得遗留失控的模型或工具任务。诊断事件不得包含凭据。

## 不做的事

- 不使用精确 tokenizer、计费估算或机器学习方法优化摘要策略。
- 不按模型名称自动推断上下文窗口；窗口大小由配置指定。
- 不保证摘要保留所有细节；需要精确内容时通过重新读取原始文件或持久化结果获取。
- 不在本章引入跨会话历史持久化、长期记忆、向量检索或语义搜索。
- 不在本章实现会话恢复命令或 TUI 入口；已有或后续恢复流程只需复用同一持久会话 ID 定位结果目录。
- 不迁移、兼容或自动清理旧 `.mew/context` 内容。
- 不改变现有工具的业务行为、权限策略、超时策略或工具调度分类。
- 不在活动 Agent 任务期间并发执行 `/compact`。
- 不进行无限次的紧急重试；一次紧急压缩后原请求至多重试一次。

## 验收标准

- **AC1（F1、F3）**：当单个工具结果超过阈值时，下一次模型请求历史包含预览和可读路径而非完整结果；通过该路径读取的完整内容不会再次被替换为预览。
- **AC2（F2）**：同轮多个工具结果单独均未超阈值、但累计超消息预算时，系统仅替换最大的结果，直到累计内容不再超预算。
- **AC3（F4、F5、N1）**：使用默认配置和 200K 窗口时，估算输入用量超过 167K 后会在模型请求前自动触发摘要；不超过时不触发。
- **AC4（F6、F13）**：在低于自动阈值的会话中执行 `/compact`，系统仍发起摘要请求，并向界面发出包含手动原因及前后估算值的事件。
- **AC5（F7、F8、F9）**：摘要请求明确禁止工具调用；其正式摘要包含九段结构，分析草稿不出现在重建历史；重建边界消息要求模型重新读取缺失细节。
- **AC6（F9）**：压缩后至少保留约 10K Token 或 5 条近期消息，且任一保留的工具调用均与对应结果完整成组出现。
- **AC7（F10）**：多轮 `/plan` 可触发压缩，规划结束后共享会话历史与规划开始前一致；普通执行和 `/do` 的压缩会更新共享历史。
- **AC8（F11）**：连续三次自动摘要失败后，系统不再自动摘要；随后 `/compact` 成功时失败计数清零，自动压缩重新可用。
- **AC9（F12）**：自动熔断后估算用量达到强制线仍执行压缩；模型返回上下文超限时，只压缩并重试原请求一次。
- **AC10（F13、N2、N4）**：所有阈值均可通过配置覆盖且非法组合被拒绝；两个现有 Provider 均可在测试替身下执行压缩流程；自动化测试不访问真实模型服务。
- **AC11（F1、N5）**：新建且未产生需持久化结果的会话结束后，不存在对应 context 目录；首次超过阈值的结果才创建 `.mewcode/context/<持久会话 ID>/tool-results/`。
- **AC12（F1、N5）**：以同一持久会话 ID 恢复后的会话可读取恢复前的结果引用，且新的大结果写入同一目录而不覆盖旧结果；没有持久会话 ID 时工具结果保留原文且任务不失败。
