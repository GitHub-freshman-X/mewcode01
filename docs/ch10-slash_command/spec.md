# MewCode Slash Command Spec

## 背景

MewCode 现有 TUI 只对少量以 `/` 开头的输入做硬编码分支，无法统一提供帮助信息、别名校验、参数提示和 Tab 补全。清屏、查看状态和模式切换等高频确定性操作无需进入 Agent Loop；将它们交给模型既会增加延迟，也会消耗对话 Token，且模型无法直接完成 UI 层操作。

## 目标

- 为斜杠命令提供统一的注册、解析、分发与补全机制，使常用操作走本地快车道。
- 让命令按本地执行、影响界面状态、预设提示词转发三种方式运行，同时保持普通对话的既有 Agent 流程。
- 提供可发现、可预测的九个内置命令，并在状态栏清晰显示当前默认或计划模式。

## 功能需求

- **F1 命令注册**：系统在启动阶段登记每个命令的名称、别名、简短描述、用法、执行类型、可选参数提示、隐藏标记和处理逻辑；名称或别名重复时立即失败退出。
- **F2 命令解析与查找**：仅以 `/` 开头的输入进入命令解析；第一个空白符前为命令名，其后为参数；命令名大小写不敏感。空输入不触发操作，未知命令提供 `/help` 引导，单独输入 `/` 显示可见命令。
- **F3 执行类型**：命令分为本地、影响界面状态和预设提示词三类。本地及界面状态命令不进入 Agent Loop；预设提示词命令通过既有对话通道交给 Agent。
- **F4 界面控制边界**：命令通过独立的界面控制能力显示反馈、发送用户消息、切换模式、读取 Token 并刷新状态，不依赖具体 TUI 渲染实现。
- **F5 输入分流**：用户回车时优先判断是否为命令；命令由本地系统处理，普通文本维持既有 Agent 对话行为。
- **F6 Tab 补全**：补全不包含隐藏命令；唯一匹配直接写入输入框，多个匹配展示候选菜单供用户选择。
- **F7 内置命令**：系统提供 `/help`、`/compact`、`/clear`、`/plan`、`/do`、`/session`、`/memory`、`/status`、`/review` 共九个内置命令；别名和详细交互遵循本章参考文档。
- **F8 模式命令**：`/plan` 无参数时切换计划模式；`/plan <需求>` 进入计划模式并提交需求；在计划模式再次执行 `/plan` 退出。`/do` 用于切回默认执行模式。
- **F9 状态栏**：状态栏始终显示 `[DEFAULT]` 或 `[PLAN]`，并保留 Token 与 `/help` 提示。
- **F10 命令显示顺序**：本地命令的文本及系统反馈以真实交互顺序插入聊天视图，例如“任务 1 → 命令 → 系统反馈 → 任务 2”；这些显示条目不写入会话历史或模型请求。
- **F11 会话标题**：`/session list` 为每个会话显示 ID 与标题。标题取该会话首条用户文本，去除首尾空白；过长时按字符边界截断并显示省略号；空会话显示明确占位标题。

## 非功能需求

- **N1 启动校验**：启动时完成所有命令定义校验；同一名称、名称与别名、或不同别名之间均不得重复，错误须能定位冲突标识。
- **N2 本地性能**：命令解析、查找与补全为纯本地操作；普通本地命令不得发起模型请求或消耗对话 Token。
- **N3 可测试性与解耦**：注册、解析、查找和补全逻辑可在不启动交互界面的情况下自动测试，且不绑定具体渲染框架。
- **N4 安全可观测性**：关键执行边界接入既有结构化日志，仅记录命令名、执行类型、结果状态、耗时及候选数等安全元数据；不得记录用户参数、预设提示词正文、会话正文、Token 或密钥。
- **N5 兼容性**：普通对话、任务取消、权限确认和既有模式行为不得回归；`/plan` 与 `/do` 的模式变化应立即反映在状态栏。
- **N6 配置范围**：本章不新增可配置项，不修改 `.mewcode/config.example.yaml`；新增内置命令通过代码注册。
- **N7 标题成本与兼容性**：会话标题仅基于本地已存储记录生成，不调用 LLM、不增加网络请求，也不修改既有 JSONL 持久化格式。

## 不做的事

- 不支持用户自定义命令、配置文件注册或运行期动态增删命令。
- 不支持动态生成预设提示词，也不提供命令级权限控制。
- 不将 MCP prompts 或其他外部来源自动注册为命令；该扩展留给后续 Skill 系统。
- 不新增会话、记忆、压缩或权限系统的底层能力；命令仅调用第八、九章已具备的能力。
- 不改变既有 Agent Loop、Provider 协议、权限决策机制或持久化格式。
- 不实现命令历史、引号或转义参数语法、模糊匹配或多级子命令补全。
- 不支持手动编辑、重命名、搜索或固定会话标题，也不使用 LLM 生成标题。
- 不新增远程服务、网络依赖或可配置项。

## 验收标准

- **AC1（F1、N1）**：应用启动时，重复名称或别名会立即失败，并说明冲突标识；无冲突时所有九个内置命令可被查询。
- **AC2（F2）**：`/HELP`、`/h` 等大小写或别名输入命中正确命令；`/` 显示可见命令；未知命令提示使用 `/help`；空输入不调用 Agent。
- **AC3（F3、F4）**：`/help`、`/status` 等本地命令可直接显示结果，且不启动 Agent 任务；`/review <关注点>` 将预设审查需求及附加关注点送入既有 Agent 对话通道。
- **AC4（F8、F9、N5）**：`/plan` 在默认模式进入计划模式，状态栏显示 `[PLAN]`；再次执行 `/plan` 回到默认模式并显示 `[DEFAULT]`；`/plan <需求>` 进入计划模式并将需求交给 Agent；`/do` 从计划模式回到默认执行模式。
- **AC5（F5、N5）**：回车提交 `/...` 时由命令系统处理，非斜杠文本仍以原有方式发给 Agent；输入框、任务取消和权限确认交互保持正常。
- **AC6（F6）**：Tab 补全排除隐藏命令；唯一匹配直接写入输入框；多个匹配提供可选候选项。
- **AC7（F1、F2）**：命令缺少必需参数时显示该命令的参数提示；帮助页包含命令名称、别名、说明及用法。
- **AC8（N3）**：自动化测试覆盖注册冲突、解析、别名、未知命令、补全、分流、模式切换和提示词转发；项目构建及既有测试通过。
- **AC9（N4）**：命令关键生命周期日志仅含安全元数据，不含用户参数或提示词正文。
- **AC10（F10）**：连续执行任务、命令、任务时，命令文本与对应系统反馈位于两次任务之间，顺序稳定，且不进入 Session history、JSONL journal 或后续模型请求。
- **AC11（F11、N7）**：`/session list` 显示每个会话的 ID 与首条用户消息标题；长标题显示截断与省略号，空会话显示占位标题；整个流程不发起额外 API 请求。
