# MewCode System Prompt Spec

## 背景

MewCode 已完成流式多轮对话、工具系统、Agent Loop，以及 `/plan` 与 `/do` 两阶段工作流。当前提示词能力仍主要散落在普通用户消息和模式前缀里：全局行为约束不成体系，规划模式指令以用户文本形式注入，工具使用约定主要依赖工具描述本身，环境信息、动态模式要求和稳定身份/行为规则也没有清晰分层。

这会带来三类问题：模型遵守关键约定的稳定性不足，稳定指令无法独立走缓存通道，运行时补充指令容易污染对话历史或被模型当作用户输入回应。本章将把原本零散的全局指令扩展为结构化 System Prompt 体系，让 MewCode 在保持第 4 章 Agent Loop 行为边界的同时，拥有更稳定、更便宜、更可验证的系统级指令注入能力。

## 目标

- 将全局系统指令按职责拆分为可排序、可扩展的模块，并按优先级稳定拼装。
- 明确区分稳定提示内容与动态运行内容，使稳定指令和工具描述可进入 Provider 支持的缓存路径。
- 支持系统级动态补充消息，用于注入环境信息、任务模式要求和会话级开关，而不把这些内容当作普通用户输入。
- 在全局系统指令和工具描述中双重强化关键行为规则，提升模型对工具优先级、编辑前读取、规划只读等约定的遵守率。
- 为 `/plan` 等会话级模式提供按轮次控制的补充指令注入策略，兼顾遵守率和 Token 成本。
- 从 Provider 响应中提取缓存命中相关用量信息，并以统一方式暴露给 Agent 事件和测试。
- 准备一组典型人工对比场景，用于定性评估提示词改造前后的行为差异。
- 本章文档存放于 `docs/ch05-system_prompt/`，并在文档索引中登记。

## 功能需求

- **F1 系统提示模块化**：系统提供结构化的 System Prompt 组织方式，将固定全局指令拆成身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出七个固定模块，并支持环境信息作为最后的基础动态段落。
- **F2 模块优先级拼装**：系统必须按稳定优先级拼装提示模块：身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出、环境信息。模块之间使用空行分隔，输出文本顺序确定，便于测试、审阅和后续插入新模块。
- **F3 可选模块扩展**：系统支持在固定模块之后追加自定义指令、已激活 Skill、长期记忆等可选模块。可选模块不存在时不得输出空标题或占位文本；存在时必须保持确定顺序。
- **F4 稳定与动态内容分离**：系统必须区分稳定提示内容和动态运行内容。稳定内容包括固定全局指令、稳定工具说明和可缓存的长期说明；动态内容包括当前工作区、操作系统、当前日期、会话级模式、轮次补充指令和用户任务上下文。
- **F5 可缓存提示通道**：当 Provider 支持提示缓存时，稳定系统指令和稳定工具描述应进入可缓存通道；动态环境信息、对话历史、当前用户请求和按轮次变化的补充指令不得污染稳定缓存段。
- **F6 Provider 中立请求模型**：Agent 与上层模块只依赖统一的提示词请求抽象，不直接拼接某个模型厂商特有的系统消息或缓存字段。具体 Provider 负责把统一抽象映射为各自 API 的请求格式。
- **F7 系统级动态补充消息**：系统支持一种带特殊标签的补充消息形式，用于在运行中注入环境信息、任务模式要求和临时系统级约束。该补充消息必须被模型理解为系统级指令，不得作为普通用户输入展示或进入用户可见对话历史。
- **F8 环境信息注入**：每次模型请求都应携带当前运行环境信息，至少包括工作区路径、操作系统、Shell、当前日期、当前任务模式和可用工具范围。环境信息必须位于动态通道，且内容变化不应导致稳定提示缓存失效。
- **F9 工具规则双重强化**：关键工具使用规则必须同时出现在全局工具使用模块和具体工具描述中。至少覆盖：优先使用专用工具完成可执行操作、编辑前必须先读取目标文件、搜索优先使用搜索工具、写入/修改前注意工作区边界、规划模式不得使用副作用工具。
- **F10 工具描述稳定化**：工具面向模型的名称、用途说明、参数约束和关键行为规则应以稳定文本输出；除非工具集合或工具语义变化，否则同一工具定义在不同请求中保持一致，以便进入缓存路径并减少行为漂移。
- **F11 会话级模式补充策略**：系统支持按轮次注入会话级模式指令。对同一任务，首轮注入完整模式说明；达到配置的间隔轮次时重复关键规则；其他轮次只注入精简提醒或不注入，以控制 Token 成本。
- **F12 Plan Mode 指令迁移**：`/plan` 的只读探索、禁止修改、最终输出计划等约束必须从普通用户提示前缀迁移到系统级动态补充消息。用户任务文本应保持为用户任务本身，不混入系统约束。
- **F13 Do Mode 指令整理**：`/do` 的计划执行语义应保留为明确的任务上下文，但全局执行规则、工具规则和环境信息由系统提示体系承担，避免把长期行为规则重复塞进用户任务文本。
- **F14 对话历史隔离兼容**：本章必须保持第 4 章历史边界：普通执行轮次完整提交，Plan Mode 临时探索历史不泄漏到共享历史，系统级补充指令不进入用户可见历史，也不作为后续普通对话的用户消息保存。
- **F15 缓存命中观测**：当 Provider 响应包含缓存创建、缓存命中或缓存读取相关用量字段时，系统应解析并以统一用量结构暴露。Provider 未报告相关字段时，应明确表示不可用或零值，不得伪造命中。
- **F16 缓存策略验证**：系统提供可测试方式验证稳定提示内容在连续请求中保持不变、动态内容在消息通道中变化、Provider 请求体包含预期缓存标记或可观测字段。
- **F17 人工对比场景**：本章交付一组典型人工对比场景，用于观察改造前后模型行为差异。至少覆盖：编辑前是否读取、搜索任务是否使用搜索工具、规划模式是否保持只读、`/do` 是否不受规划只读约束污染、环境信息是否被正确使用。
- **F18 回归兼容**：普通非命令输入、工具调用循环、`/plan`、连续多个计划、`/do`、取消和错误停止行为必须保持第 4 章定义的外部语义；提示词改造不得改变工具安全调度和计划消费边界。
- **F19 跨平台 Shell 环境兼容**：环境信息注入必须在 Windows、macOS 与 Linux 的常见终端中可用。系统应优先使用当前平台提供的 Shell 信息；Windows 缺少 Unix `SHELL` 环境变量时，必须从 Windows 约定的环境变量推导，或使用明确的安全回退值，且不得因此阻止模型请求。

## 非功能需求

- **N1 Provider 中立性**：提示词构建、模式注入和缓存观测的核心语义不绑定 OpenAI 或 Anthropic 的请求格式；新增 Provider 时应能复用同一套上层提示词抽象。
- **N2 确定性**：相同输入、相同配置和相同工具集合下，稳定系统指令、工具描述和模块顺序必须完全一致；动态字段只在对应动态通道变化。
- **N3 可测试性**：系统提示拼装、动态补充消息、Provider 请求映射、缓存用量解析和模式注入频率都必须可在不访问真实模型服务的情况下自动测试。
- **N4 可诊断性**：请求构建失败、缓存字段不可用、模式补充指令缺失或环境信息缺失时，应返回有诊断价值的错误或测试可观察结果，不应静默降级为普通用户消息。
- **N5 成本控制**：稳定大段提示应尽量复用缓存；动态补充指令应按策略控制重复频率，避免每轮重复注入完整长文本。
- **N6 安全边界清晰**：提示词不得扩大工具实际权限。Plan Mode 的只读能力仍由工具注册表过滤保证；系统提示只强化语义，不替代第 4 章已有的工具安全边界。
- **N7 历史与展示隔离**：系统级补充内容不得出现在 TUI 的普通用户消息展示中，也不得作为用户消息提交到共享会话历史；用户仍只看到自己输入的任务、模型输出和工具状态。
- **N8 兼容性**：未配置新提示词选项时，MewCode 应自动使用安全默认系统提示；现有配置文件、模型选择、Thinking 配置、最大 Token 和 Agent 迭代配置继续有效。
- **N9 可扩展性**：新增固定模块、可选模块、任务模式或动态环境字段时，应通过追加配置或模块注册完成，避免改动 Provider 业务逻辑。
- **N10 文本可审阅性**：生成的系统提示应结构清晰、标题稳定、空行分隔一致，便于人工审阅和快照测试；不输出无意义占位符。
- **N11 API 契约谨慎性**：Provider 适配器必须按各自 API 支持能力表达系统消息、工具描述和缓存标记；如果某个 Provider 不支持某项缓存或用量字段，应保持请求可用并明确报告不支持。
- **N12 回归稳定性**：第 2 章到第 4 章已有自动测试应继续通过；提示词改造不得引入半轮历史、工具结果错配、计划丢失或事件终态重复。
- **N13 平台可移植性**：Shell 信息仅用于向模型描述运行环境，缺失某一平台特有环境变量时不得使正常的交互式任务不可用。

## 不做的事

- 不做项目级指令文件加载，例如 `AGENTS.md`、`CLAUDE.md` 或仓库内自定义规则的自动发现与合并。
- 不做自动记忆、长期记忆的生成、更新、压缩或持久化；本章只保留长期记忆作为可选模块插槽。
- 不做真实 MCP 接入、MCP 工具发现或 MCP 工具描述同步。
- 不做自动化评估系统、评分器、批量基准测试或模型行为统计报表；本章只准备人工对比场景。
- 不做上下文压缩、历史摘要、长会话裁剪或 Token 预算调度。
- 不做工具权限审批、沙箱策略、用户确认流程或工具执行安全模型升级。
- 不新增业务工具，也不改变第 3 章六个核心工具的实际执行行为。
- 不改变第 4 章 Agent Loop 的停止条件、工具调度算法、计划消费规则或 Plan Mode 临时历史隔离语义。
- 不保证所有 Provider 都实际产生缓存命中；系统只在 Provider 支持且响应报告相关字段时解析和展示。
- 不把提示词遵守率作为硬性自动验收指标；遵守率通过人工场景观察作为定性评估。
- 不提供用户界面的提示词编辑器、模块开关面板或可视化调试页。
- 不持久化会话级开关或模式注入状态；相关状态仅服务当前 Agent 任务。

## 验收标准

- **AC1（F1、F2、N2、N10）**：使用同一环境和同一工具集合构建系统提示时，输出包含七个固定模块与环境信息，顺序严格为身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出、环境信息，模块之间以空行分隔，连续构建结果完全一致。
- **AC2（F3）**：未提供自定义指令、Skill 或长期记忆时，系统提示不出现空模块标题；提供这些可选内容时，它们按自定义指令、已激活 Skill、长期记忆的顺序追加在固定模块之后。
- **AC3（F4、F5、F8）**：连续两次请求仅当前日期、工作区路径或任务模式不同的情况下，稳定系统指令和稳定工具描述保持不变，动态环境信息出现在动态通道中，且不会改变稳定缓存段。
- **AC4（F6、N1）**：Agent 发起模型请求时只传递统一提示词抽象；OpenAI 与 Anthropic 适配器分别将该抽象映射为自己的请求格式，Agent 层不包含 Provider 专有缓存字段。
- **AC5（F7、F14、N7）**：系统级动态补充消息进入模型请求，但不出现在 TUI 用户消息展示中，不进入共享会话历史，也不会作为普通用户消息被后续轮次复用。
- **AC6（F8）**：任意普通任务首轮请求均包含工作区路径、操作系统、Shell、当前日期、当前任务模式和可用工具范围；缺失必填环境字段时，请求构建失败并返回可诊断错误。
- **AC7（F9、F10）**：工具定义中可观察到关键规则强化文本；全局工具使用模块中也包含同类规则。读文件、写文件、改文件、执行命令、找文件、搜索代码的工具定义在相同配置下连续构建完全一致。
- **AC8（F11）**：配置模式补充指令间隔后，同一 Agent 任务第 1 轮包含完整模式说明，达到间隔的轮次包含关键规则提醒，其余轮次仅包含精简提醒或不包含补充指令，实际请求序列与配置一致。
- **AC9（F12、F14、F18）**：执行 `/plan <任务>` 时，用户任务消息只包含用户任务本身；只读探索、禁止修改和最终输出计划等约束位于系统级动态补充消息；共享历史仍不包含 Plan Mode 探索轮次。
- **AC10（F13、F18）**：存在多个待执行计划时执行 `/do`，请求仍按顺序携带全部计划，且系统提示承担通用执行规则、工具规则和环境信息；`/do` 不包含 Plan Mode 的只读补充指令。
- **AC11（F15、N11）**：Provider 响应包含缓存创建、缓存命中或缓存读取相关字段时，统一用量结构能暴露对应数值；Provider 不返回这些字段时，统一结构明确表示不可用或零值，且不会影响任务正常完成。
- **AC12（F16）**：使用脚本化 Provider 或请求体快照测试连续两次相同稳定提示的请求，能够观察到预期缓存标记或可缓存段位置；动态环境信息变化不会破坏稳定段快照。
- **AC13（F17）**：人工对比场景文档包含至少五个场景：编辑前读取、搜索优先使用搜索工具、规划模式只读、`/do` 不受只读规划污染、环境信息正确使用；每个场景说明输入、观察点和期望行为。
- **AC14（F18、N6、N12）**：第 4 章已有 Agent Loop、Plan Mode、Do Mode、工具调度、历史隔离和计划消费相关自动测试继续通过；提示词改造不改变工具实际权限和执行调度。
- **AC15（N3、N4、N8、N9）**：新增提示词构建、动态注入、Provider 映射、缓存用量解析和注入频率测试均可离线运行；未配置新提示词选项时系统使用默认提示词并保持请求可用。
- **AC16（F19、N13）**：在缺少 `SHELL` 的模拟 Windows 环境中构建环境信息成功，生成的 Shell 字段非空；在 Unix 环境中仍优先保留 `SHELL` 的值。环境信息随后可被构建为系统消息，且不触发 `prompt environment requires shell`。
