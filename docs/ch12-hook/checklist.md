# MewCode Hook 生命周期钩子 Checklist

> 每项以可观察行为或实际命令验证。实施完成后在本文件记录命令、结果与必要的失败说明。

## 规则、事件与配置

- [ ] 三层配置中的 `hooks` 均可加载，规则按用户级、项目级、本地级的固定顺序追加；缺失文件或 `hooks` 字段不影响启动。（验证：使用临时三份配置分别声明可观测动作，启动并比较执行顺序。）
- [ ] 规则必须包含合法事件和动作，条件缺失时在目标事件无条件执行。（验证：加载无 `if` 的规则并触发其事件；分别省略事件或动作，断言加载错误含规则序号/标识和字段。）
- [ ] 会话、轮次、消息、工具与已能可靠观察到的系统事件在对应时机触发，动作能读取该事件可用的上下文。（验证：记录脚本化 Agent 任务的 Hook 事件及上下文字段。）
- [ ] 未知事件、未知动作类型、缺少动作必填字段、非法超时、非工具前事件 `reject`、工具前事件 `async` 均在加载期被拒绝。（验证：逐项加载非法 YAML，检查错误包含文件路径、规则标识或序号与字段。）

## 条件与变量

- [ ] 精确、反向、正则和 glob 条件均按工具名、事件名和工具参数字段正确匹配。（验证：用同一事件构造命中与未命中的上下文，比较执行的规则标识。）
- [ ] 多条件全满足与任一满足分别遵从预期；同一条件混用 `&&` 和 `||` 被拒绝。（验证：运行真假组合矩阵并加载混用样例。）
- [ ] `$EVENT`、`$TOOL_NAME`、`$FILE_PATH`、`$MESSAGE`、`$ERROR` 与 `$TOOL_ARGS.<name>` 被替换为事件上下文，未知字段与变量替换为空字符串。（验证：对命令、提示词和 HTTP body 使用全部变量并检查渲染结果。）

## 工具前拦截与工具后通知

- [ ] `pre_tool_use` 在权限判断和真实工具执行之前同步运行；匹配拒绝规则后真实工具执行次数为零。（验证：以计数测试工具配合拒绝规则运行 Scheduler。）
- [ ] 拒绝规则的输出成为标准失败工具结果并写回模型，模型下一轮能根据原因改用允许调用。（验证：脚本 Provider 先请求被拒绝调用、后请求允许调用，检查第二次请求及终态。）
- [ ] 多个工具前规则按声明顺序运行，首个拒绝使后续 Hook 和该工具均不执行。（验证：配置多个计数动作，比较调用序列。）
- [ ] 不拒绝的工具前 Hook 不改变现有权限、确认、只读并发批次或工具结果原始顺序；Hook 不能放行被权限系统拒绝的调用。（验证：运行现有权限和调度场景，并同时配置允许型 Hook。）
- [ ] `post_tool_use` 在工具结果生成后接收相同工具上下文；其失败不影响工具结果回灌或 Agent 终态。（验证：使工具后命令失败，检查模型历史和完成状态。）

## 动作与执行控制

- [ ] command 动作在变量替换后执行，成功、非零退出和超时均生成可诊断状态；超时子进程被终止，非拒绝失败不终止 Agent。（验证：使用短命令、失败命令和超时命令分别运行。）
- [ ] prompt 动作生成下一次模型请求可见的 Hook 通知，但不会修改 System Prompt；通知仍经过正常历史/上下文压缩路径。（验证：捕获连续 Provider 请求和 System Prompt，并触发一次压缩。）
- [ ] HTTP 动作按配置方法和渲染后的 body 请求本地测试服务；不可达或失败响应只记录失败，不阻塞 Agent。（验证：使用 `httptest` 服务及不可达地址比较任务终态。）
- [ ] agent 动作可通过配置校验，触发时返回“运行时未接入”的可诊断结果，不启动真实子 Agent 且不中断主流程。（验证：触发默认 AgentRunner 并检查无额外 Agent 任务。）
- [ ] `once: true` 在同一 Engine 生命周期只执行一次，重建 Engine 后可再次运行。（验证：同事件连续触发两次，再构造新的 Engine 触发一次。）
- [ ] 异步 Hook 不阻塞主流程，失败被隔离；工具前 Hook 不允许异步。（验证：以受控阻塞动作验证任务继续，以失败动作检查日志；加载工具前异步样例应失败。）

## 可观测性、兼容性与回归

- [ ] Hook 匹配、执行、跳过、拒绝、失败和完成日志包含事件、规则标识、动作类型、状态、异步标记与安全的计数/耗时/状态码字段。（验证：检查运行产生的 JSONL 日志。）
- [ ] Hook 日志不含提示词正文、工具结果正文、HTTP 请求头、密钥或未经脱敏的错误载荷。（验证：在各载荷中放入唯一敏感占位文本，再搜索日志文件，结果为空。）
- [ ] 无 Hook 配置时，普通对话、`/plan`、`/do`、`/compact`、权限确认、工具调度、取消和 Token 统计保持原有行为。（验证：运行现有 Agent、权限、命令与 TUI 回归测试。）
- [ ] Hook 条件、配置、执行器、Engine、Runner、Scheduler 与启动装配均可不访问真实模型或外部网络地自动测试。（验证：`go test ./internal/hooks ./internal/agent ./cmd/mewcode` 通过。）
- [ ] 格式化、全量测试和 CLI 构建均通过，且工作区仅包含本章预期改动。（验证：运行 `gofmt -w`、`go test ./...`、`go build ./cmd/mewcode` 与 `git status --short`。）

## 端到端场景

- [ ] 自动格式化：配置 `post_tool_use` 的 WriteFile 条件与 command 动作；Agent 写入匹配源文件后格式化命令运行，工具结果仍被模型收到。（验证：脚本 Provider 请求写文件并检查格式化标记、模型历史与任务完成。）
- [ ] 安全兜底：配置 `pre_tool_use` 的高危命令正则和 `reject: true`；模型首次调用被拒绝、收到原因后改用安全命令，真实高危命令从未启动。（验证：脚本 Provider 完整运行两轮。）
- [ ] 会话提示与通知失败：在会话开始配置一次性 prompt Hook、在工具后配置不可达异步 HTTP Hook；首次模型请求看到提示通知，HTTP 失败后任务仍成功完成，后续触发不重复注入提示。（验证：记录连续请求、任务终态和脱敏日志。）
