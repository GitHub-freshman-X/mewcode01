# MewCode Hook 生命周期钩子 Spec

## 背景

MewCode 已有工具执行、Agent Loop、权限决策、上下文管理和 Skill 等能力，但开发者仍需反复手动执行触发条件明确且动作固定的工作：写入代码后格式化、修改特定文件后生成产物、会话开始时补充项目上下文，以及在工具调用前检查更细粒度的安全约束。现有权限系统负责统一的准入决策，却不适合表达“某个生命周期事件发生后自动做一件事”的可配置自动化。

本章引入 Hook 系统：用户以 YAML 声明规则，在 Agent 生命周期事件发生时按条件执行动作。它应将重复操作从人工流程中移出，同时让工具执行前的 Hook 能够基于工具参数拒绝调用，并把明确原因反馈给模型以支持后续调整。

## 目标

- 提供事件、可选条件和动作组成的声明式 Hook 规则。
- 覆盖会话、轮次、消息、工具及必要的系统生命周期事件。
- 允许工具执行前的 Hook 拦截调用，并以工具结果向模型反馈拒绝原因。
- 提供命令、提示词、HTTP 和子 Agent 四种动作类型，其中子 Agent 仅完成可校验的占位接入。
- 支持一次执行、异步执行和命令超时控制，同时保证 Hook 故障不破坏 Agent 主流程。
- 从用户级和项目级 YAML 配置加载并追加合并规则，在启动或加载阶段集中校验。

## 功能需求

- **F1 规则三要素**：系统加载的每条 Hook 规则必须包含事件和动作；可选条件缺失时视为无条件匹配。规则可有稳定标识，供诊断和日志关联。
- **F2 生命周期事件**：系统至少支持会话开始与结束、轮次开始与结束、消息发送前与接收后、工具执行前与执行后，以及启动、关闭、错误、上下文压缩、权限请求、文件变更和 Slash Command 执行等系统事件。每次事件触发均向匹配规则提供该事件可用的上下文。
- **F3 条件匹配**：条件支持精确匹配、反向匹配、正则匹配和 glob 匹配，并可选择“全部满足”或“任一满足”组合多个子条件。单一规则内不得混用两种组合方式；未知上下文字段按空值处理，不导致运行失败。
- **F4 条件上下文**：条件至少可读取事件名、工具名和工具参数字段；动作模板还可读取事件名、工具名、文件路径、消息、错误信息和具名工具参数。当前事件未提供的变量展开为空字符串。
- **F5 工具前拦截**：工具执行前事件必须在真实工具动作开始前同步运行。匹配且标记为拒绝的规则取消该工具调用，不执行真实工具，并将其动作输出作为可诊断的工具失败结果反馈给模型；模型可在下一轮调整策略。多个匹配规则按配置出现顺序执行，首个拒绝终止本次 Hook 与工具执行。
- **F6 非拦截事件**：除工具执行前事件外，Hook 仅执行附加动作，不能取消既有 Agent 主流程或已完成的工具调用。工具执行后事件应在工具结果产生后收到对应工具上下文。
- **F7 命令动作**：命令动作在替换上下文变量后执行 shell 命令，捕获安全摘要、退出状态和输出；可配置最长执行时间，超时后终止该命令并记录失败。
- **F8 提示词动作**：提示词动作将渲染后的内容作为 Hook 通知追加到后续模型可见的对话上下文，而不修改既有 System Prompt 前缀；通知可随正常上下文压缩处理。
- **F9 HTTP 动作**：HTTP 动作按配置的方法、URL、头和请求体发送经变量替换后的通知，并报告可诊断的成功或失败状态。
- **F10 子 Agent 动作占位**：系统接受并校验子 Agent 动作配置，调用预留的运行接口；本章不启动真实子 Agent。未接入运行时的结果须明确表明该动作尚不可执行，但不得影响主流程。
- **F11 执行控制**：规则可声明本进程生命周期内只执行一次；被标记后后续匹配跳过，重启后重置。规则可声明后台异步执行；工具执行前事件不得配置为异步。异步 Hook 不阻塞 Agent 的后续主流程。
- **F12 故障隔离**：除有效的工具前拒绝外，任意 Hook 的匹配、模板展开、动作执行或异步任务失败只记录安全元数据日志，不中断 Agent Loop、会话或其余工具调度。
- **F13 配置来源与合并**：系统从 `os.UserConfigDir()/mewcode/config.yaml` 和项目根目录 `.mewcode/config.yaml` 读取 Hook 规则。各来源的有效规则按用户、项目的固定顺序追加合并，而不是任一文件存在即停止。
- **F14 配置校验**：加载时必须拒绝未知事件、未知动作类型、缺失动作必填字段、非法条件表达式、将拒绝用于非工具前事件，以及将异步用于工具前事件的配置。错误信息须定位到规则标识或序号及字段。
- **F15 可观测性**：关键阶段至少记录事件类型、规则标识、动作类型、执行状态、是否异步、耗时、退出状态或响应状态等安全元数据。不得记录提示词正文、工具结果正文、请求头、密钥或未经脱敏的错误载荷。

## 非功能需求

- **N1 安全性**：Hook 不得绕过已有权限、工作区沙箱或危险命令黑名单；工具前拦截只能额外拒绝调用。
- **N2 稳定性**：相同输入与配置下，同步 Hook 的匹配、执行顺序和拦截结果必须确定；异步完成顺序不作保证。
- **N3 可测试性**：事件分发、条件语法、变量展开、每种动作、配置校验、一次执行、异步限制、拒绝反馈和故障隔离均可不访问真实模型或外部网络地自动测试。
- **N4 兼容性**：未配置 Hook 时，既有 Agent Loop、权限、配置加载、工具调度和对话行为保持不变。
- **N5 配置可审阅性**：YAML 结构、允许的事件与动作字段、条件错误和约束应清晰、有限且可诊断。

## 不做的事

- 不在本章启动或管理真实子 Agent；仅保留后续章节可对接的动作接口。
- 不持久化“只执行一次”状态，也不提供跨进程恰好一次语义。
- 不提供规则显式优先级、排序字段或依赖图；同事件规则仅按合并后的声明顺序处理。
- 不实现 Hook 的图形化编辑、热更新界面、远程同步、共享市场或审计报表。
- 不把 HTTP 动作扩展为通用网络安全策略、重试系统或队列；网络访问仍遵守现有安全边界。
- 不替换或弱化现有权限系统；Hook 不能用于放行原本被权限系统拒绝的操作。

## 验收标准

- **AC1（F1、F2、F13）**：给定两个配置来源中声明的会话、轮次、消息、工具和系统事件规则，启动并执行一轮任务后，可观察到全部有效规则按固定合并顺序匹配；省略条件的规则在对应事件上执行。
- **AC2（F3、F4）**：分别使用精确、反向、正则、glob 及“全部满足”/“任一满足”条件驱动相同事件，只有期望规则执行；混用组合符或引用未知字段的配置得到明确校验结果或空值匹配行为。
- **AC3（F5）**：模型请求一个满足工具前拒绝规则的工具调用时，真实工具的执行计数为零，模型历史收到包含拒绝原因的工具失败结果，并能在下一轮改用允许的调用完成任务。
- **AC4（F5、F6、N1）**：多个工具前规则中前序拒绝时后续规则和真实工具均不执行；工具后或其他事件即使声明拒绝也被配置校验拒绝，且既有权限拒绝仍不能被 Hook 放行。
- **AC5（F7、F11、F12）**：命令动作正确展开文件路径等变量并运行；命令超时或退出失败时记录失败，Agent 仍继续。工具前命令在完成前阻塞以产出允许或拒绝结果。
- **AC6（F8）**：会话开始的提示词 Hook 生成模型可见的通知，同时原 System Prompt 内容保持不变；上下文压缩后该通知遵从正常历史处理。
- **AC7（F9、F12）**：HTTP 动作向可控测试服务发送替换后的方法和请求体；服务不可达或返回失败时，Agent 任务仍正常推进，日志不含敏感请求内容。
- **AC8（F10）**：合法的子 Agent 动作配置加载成功，触发时得到“运行时未接入”的可诊断结果且 Agent 主流程不中断。
- **AC9（F11、F14）**：一次执行规则在同一进程后续触发中跳过、重启后可再次运行；工具前异步、非工具前拒绝、未知事件、未知动作、缺失字段和非法条件均在加载时被拒绝并定位到规则。
- **AC10（F12、F15、N3、N4）**：故意让同步和异步 Hook 动作失败后，Agent Loop 仍按原工具调度和终态完成；自动测试可验证安全日志字段而不暴露正文；无 Hook 配置时现有相关回归测试通过。
